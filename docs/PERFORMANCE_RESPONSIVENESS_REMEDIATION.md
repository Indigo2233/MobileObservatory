# 性能与响应性问题账本

> 2026-10-14 在 vivo V2324HA（Android 16 / API 36）完成首轮复现。本文记录推镜引导及跨页面性能问题的证据、修复顺序和验收状态。交互行为遵循 [全应用交互规范](INTERACTION_GUIDELINES.md) 与 [观测流程设计](OBSERVING_WORKFLOW_DESIGN.md)。

## 1. 基线与复现

推镜引导停留在“曝光与镜头”区域，使用 Android `gfxinfo framestats` 隔离采样：

| 场景 | 样本 | 基线结果 |
|---|---:|---|
| 页面静止 5 秒 | 114 帧 | 帧耗时中位数 27 ms；26.32% 错过系统截止时间；按 16.7 ms 标准为 100% 慢帧 |
| 连续拖动曝光滑块 | 3002 帧 | 20.29% 错过系统截止时间；85.28% 超过 16.7 ms；606 个慢 UI 线程帧 |
| 镜头菜单再次点击锚点 | 连续复现 | 菜单保持展开；选择具体镜头可以关闭 |
| 强制横屏 | 连续复现 | 顶部区域占用过高、曝光卡裁切、按钮过宽、滚动位置不合理 |

真机复测继续使用同一设备、同一页面状态和同一采样命令。性能指标需同时记录系统截止时间和 16.7 ms 兼容指标，避免把不同刷新率混为一个阈值。

## 2. 问题与根因

### PERF-01：推镜页面高频大范围重组（P0）

- IMU 活跃周期为 20 ms，姿态源约以 50 Hz 发布 `SkyAttitudeFix`。
- 每个 fix 写入 `PushToScreen` 顶层 Compose 状态，并同步刷新镜筒轴估计。
- 曝光设置、菜单、流程条、引导图表和任务状态处于同一大型重组范围。

**修复边界**：保留传感器和姿态计算频率；限制 UI 发布频率，并将动态引导区域与设置区域隔离。

**验收**：拖动曝光控件时设置区域不会跟随每个姿态样本重组；推镜方向反馈仍连续；真机慢帧比例显著低于基线。

### PERF-02：控件拖动期间连续持久化（P0）

- 曝光与 ISO 滑块的每个 `onValueChange` 都保存完整设置。
- 单次保存写入相机、曝光、ISO、RAW、自动 ISO 和连拍数六个字段。

**修复边界**：拖动只更新内存；在 `onValueChangeFinished`、离页、拍摄开始、离散选项变化及镜头选择完成时保存。

**验收**：一次连续拖动只产生一次持久化；离开页面和重新进入后值保持。

### PERF-03：隐藏页面继续收集高频 Flow（P0）

- Shell 保留访问过的工作区和子页面，以保存草稿及结果。
- 隐藏页面的 Lifecycle 会降至 `CREATED`，现有 `collectAsState()` 不读取该 Lifecycle。
- 相机预览、导星预览和设备遥测可继续触发隐藏页面重组。

**修复边界**：页面状态继续保留；页面 Flow 改为生命周期感知收集，使 `CREATED` 状态暂停收集并在恢复时取得最新值。运行中的采集、叠加和设备任务继续由领域层管理。

**验收**：被覆盖页面保留草稿和结果；隐藏时停止 UI Flow 收集；返回后显示最新状态；播放器和叠加任务生命周期回归通过。

### UI-01：镜头菜单无法通过第二次点击关闭（P1）

- 当前实现依赖 Compose BOM `2023.10.01` 中 `ExposedDropdownMenuBox` 的锚点切换行为。
- vivo 上再次点击锚点不能稳定触发关闭。

**修复边界**：建立显式菜单锚点和关闭契约；同一入口再次点击、系统返回、点外部及选择镜头均关闭。

**验收**：四种关闭路径具有 Compose instrumentation 覆盖，并在 vivo 上通过。

### UI-02：横屏仍使用竖屏单列编排（P1）

- 推镜页始终使用纵向单列，流程条、引导区和曝光设置竞争有限高度。
- 旋转后沿用同一滚动状态，关键操作可能落在屏幕外。

**修复边界**：小高度宽屏采用双栏；左栏承载目标、状态及引导，右栏承载曝光与镜头设置；顶部信息压缩；旋转后关键操作可见。

**验收**：横屏、小屏、200% 字体下主操作可达，内容可完整滚动，全局 STOP 不受影响。

### UI-03：镜头显示标签重复（P2）

- 能力层使用物理焦距和传感器宽度构成精确去重键。
- 界面将等效焦距截断为整数，不同镜头可能显示为同一个 `22 mm`。

**修复边界**：标签保留足够焦距精度；仍重复时显示稳定的相机标识。

**验收**：同角色、同整数焦距的不同相机可区分，当前选择在旋转和菜单关闭后保持。

## 4. 2026-10-14 实施结果

- 曝光与 ISO 滑块通过 `onValueChangeFinished` 提交，连续拖动期间只更新 Compose 内存状态。
- 镜头菜单改为显式锚点与可聚焦 `DropdownMenu`；焦距显示保留一位小数，显示文本仍冲突时追加相机 ID。
- 宽度至少 520 dp 且宽大于高时使用双栏；右栏独立滚动，设置和主操作不再占用引导图表高度。
- 姿态源继续按 20 ms 活跃周期采样，Compose 指向状态最多按 66 ms 周期发布一次。
- 19 个保留页面/组件中的 410 处 StateFlow 订阅改为生命周期感知收集；隐藏页面进入 `CREATED` 后暂停 UI 收集。
- 全部 debug 单元测试通过；debug Lint 完成且无错误；instrumentation APK 编译通过。
- 新增 instrumentation 覆盖滑块提交、菜单切换/返回/选择、横竖屏布局及隐藏页面订阅暂停。当前连接设备仅支持 `armeabi-v7a`，与 arm64 测试 APK 不兼容，真机执行等待 vivo 重新连接。
- `Build.ps1 -NonCommercial` 成功生成 1.0.8 build 44，Sequence 保持关闭，包含 Stellarium Web 资源。

## 5. 2026-10-15 FITS 浏览器与 LP700 响应性

### PERF-04：整数 FITS 每次切换重复执行完整解码（P0）

vivo V2324HA 复现文件为 `pp_0000.fits`，25,009,920 字节，3536×3536、16 bit、RGGB、`BZERO=32768`；显示预览为 884×884。旧路径在打开文件和每次切换 LP700 时都重新读取完整文件、解析头、扫描 1250 万个源像素、降采样、去马赛克、执行色彩处理并创建 Bitmap。`readBytes()` 还会为每次操作分配约 25 MB 堆内存。

**修复边界**：原始 FITS、科学叠加和校准数据保持不变；仅优化查看器的显示预览。LP700 默认关闭，矩阵与白平衡参数保持原值。

**实施**：

- [x] 整数 FITS 使用只读文件映射，移除每次 25 MB 的 `ByteArray` 分配。
- [x] Bayer 降采样按输出像素和 CFA 相位直接读取参与平均的源样本；3536² → 884² 时读取约 313 万个样本，输出与旧版扫描全部 1250 万样本的结果一致。
- [x] 缓存去马赛克后的预显示曲线 RGB 预览；首次 LP700 切换只处理 884² 缓存像素。
- [x] 普通结果和 LP700 结果各缓存一张 Bitmap；同一文件后续往返直接复用。
- [x] Float32 叠加结果分别缓存两种显示结果，避免同一开关状态重复解码。
- [x] 新增数值回归，验证相位保持下采样与旧算法逐像素一致，并验证 LP700 往返不会改变普通预览缓存。
- [ ] 在 vivo 上记录旧版与新版的首次打开、首次开启 LP700、关闭及再次开启耗时，并检查内存峰值和最终图像。
