# 星图：主镜 / 导星双视场方案

> 状态：**双光路 + 黄虚线目标框（天空投影）已落地。** 对应 `TODO.md` 事项 6c。
>
> 场景：导星镜（或寻星镜）+ 相机负责 GOTO，主镜做目视；两条光路的焦距和终端（像面或目镜）彼此独立。同一时刻只按**一条光路**画视场。黄虚线 = 目标视场，绿实线 = 当前视场，形状由当前光路决定（相机矩形或目镜圆形均可）。

请先核对第 2 节「和现状的差别」和第 9 节「待你拍板」再让实现。

---

## 1. 目标

1. 星图上能在 **主镜** 和 **导星** 两条光路之间切换显示。
2. 每条光路独立配置：**焦距** + **终端**（目镜圆形，或相机/像面矩形）。
3. 主镜可以是相机矩形视场，导星/寻星也可以是目镜圆形，不绑死「主镜=圆、导星=矩」。
4. **同一时间只显示一条光路的视场几何**（不要主镜圆和导星矩叠在一起）。
5. 保留两套框的角色：**黄虚线 = 目标视场，绿实线 = 当前视场**。两者用同一条光路算出的同一形状。
6. GOTO / 同步 / 指向并居中仍走赤道仪，与正在看哪条光路的框无关。

典型用法：


| 光路  | 常见配置             | 星图上做什么            |
| --- | ---------------- | ----------------- |
| 导星  | 短焦寻星/导星镜 + 已连接相机 | GOTO 构图、看相机能框进什么  |
| 主镜  | 长焦主镜 + 目镜        | 切过去看目视真视场，确认目标进目镜 |

## 2. 和现状的差别（必须先对齐语义）

现在实现把「线型」和「终端种类」绑在一起，而且来自**同一条**望远镜焦距：


| 现在（代码）                                 | 用户这次要的                         |
| -------------------------------------- | ------------------------------ |
| 黄虚线 `#fov-frame` = **相机矩形**，标签「预览」     | 黄虚线 = **目标**视场（选中天体处）          |
| 绿实线 `#eyepiece-fov` = **目镜圆形**，标签「望远镜」 | 绿实线 = **当前**视场（赤道仪指向处）         |
| 目镜模式和相机模式可以**同时**各画一个框                 | 只激活一条光路；该光路是目镜则两框都是圆，是相机则两框都是矩 |
| 一套 `star_map_telescope_id` + 一套目镜/传感器  | **两套**完整光路，切换只改「用哪套算框」         |
| 两框都 `position:fixed` 钉在**屏幕正中**        | 当前框跟指向，目标框跟选中天体（见 §6；M1 可先折中）  |


如果仍把虚线当成「相机」、实线当成「目镜」，就做不到「主镜也是方形相机视场」。所以本期会**拆开**这两个维度：

```text
光路（主镜 / 导星）     → 焦距 + 目镜或像面  → 算出一个形状（圆或矩）
框的角色（当前 / 目标） → 实线 / 虚线        → 同一形状画在两个位置
```

## 3. 非目标（本期不做）

- 屏幕上同时画出主镜和导星两套几何（Stellarium Plus 可以叠很多 FOV；我们明确只要一条）。
- 第三条光路（主成像 + 导星 + 寻星）。导星和寻星共用「副光路」这一槽，用名称/预设区分。
- 把视场切换自动改 GOTO 目标或改板解焦距以外的拍摄参数。
- 旋转角 / 相机旋转后的菱形框（仍按传感器边平行于屏幕，与现在一样）。
- 离轴导星的指向偏移（主镜光轴 ≠ 导星光轴）。两框仍表示「赤道仪当前/目标坐标处、该光路的视场」；偏轴以后另开事项。
- 事项 6c 里「不跟随时把框钉在天空坐标」的完整重做，除非第 9 节选择 M1b 一起做。

## 4. 数据模型

```text
StarMapOpticsTrain
  id: PRIMARY | SECONDARY
  label: 主镜 | 导星          // UI 文案，可后改「寻星」
  telescopeId + customFlMm
  mode: EYEPIECE | SENSOR
  eyepieceId + custom fl / AFOV
  sensorId + custom um / W / H   // 含「已连接相机」
```

激活显示：`activeTrain: PRIMARY | SECONDARY`（同一时刻一个）。

计算：现有 `OpticsEquipment.computeEyepiece` / `computeSensor` 按列车各算一次，**只把 `activeTrain` 的 `FovComputation` 送给叠加层**。

形状：


| `mode`     | 当前框   | 目标框   |
| ---------- | ----- | ----- |
| `EYEPIECE` | 绿实线圆  | 黄虚线圆  |
| `SENSOR`   | 绿实线矩形 | 黄虚线矩形 |


DOM 不必再假设「圆元素 = 目镜」。更干净的做法：两个叠加层改成 **current / target**，CSS 按 mode 切换 `border-radius` 和虚实线；或保留两个 div，但由 JS 按「角色 + 形状」赋值，而不是按「目镜/相机」硬编码。

## 5. 界面

放在已有左下角 **观测工具** 面板（不新增第三个圆钮）。

1. **光路切换**：`主镜` | `导星` 两个 FilterChip。切过去立刻只画该光路的框，并记住 `star_map_active_train`。
2. **显示视场** 开关：关掉则当前/目标框都隐藏（两条光路配置仍保留）。
3. **视场设置** 仍开现有 bottom sheet。顶部同样是 `主镜` | `导星`，编辑的是该光路的焦距和终端；默认停在当前激活的光路。改副光路时**不必**把显示切过去，除非用户同时点了面板上的切换。
4. 每条光路里仍是：望远镜预设 / 自定义焦距 → 目镜或相机芯片 → 目镜或传感器参数。已连接相机继续作为传感器目录里的一项，**两条光路都可以选它**（常见是导星选已连接相机，主镜选目镜）。
5. 框上的字：`主镜 当前 0.42°` / `导星 目标 1.20°×0.80°` 这类，不再写「预览」「望远镜」。

星图图层面板不放光路切换，避免和网格混在一起。

## 6. 当前框 vs 目标框（虚实线）放在哪

两框都表示**激活光路**的同一块天区大小。


| 框   | 样式  | 钉在哪                                   |
| --- | --- | ------------------------------------- |
| 当前  | 绿实线 | 赤道仪当前 RA/Dec；未连接赤道仪则钉屏幕中央（「你正在看的这块天」） |
| 目标  | 黄虚线 | 已选天体的 RA/Dec；没有选中则隐藏                  |


这才是「虚线目标、实线当前」。跟随时：实线停在屏幕中央（因为画面已经跟着赤道仪），虚线应落在目标的天空位置，**不能**再和实线叠在正中。

现状障碍：`#fov-frame` / `#eyepiece-fov` 都是 CSS 屏幕中央（`TODO.md` 6c 未做天空投影）。

所以实现分成两档，请在第 9 节选一档作为本期范围：

**M1a（只做双光路，框仍钉屏幕中央）**

- 切换主镜/导星、独立配置、只显示一条光路的**一个**框（实线当前）。
- 选中目标时，若画面已居中到该目标，虚线会和实线重合，因此 **M1a 不画虚线**，避免两个一样的框叠在一起。
- 虚线目标框留到 M2。

**M1b（双光路 + 把框投影到天空坐标）**

- 在双光路的同时做 6c：用 Stellarium 把 RA/Dec 投到屏幕像素，移动两个 overlay。
- 未跟随、拖开星图后，实线留在赤道仪指向处，虚线留在目标处。
- 工作量和风险明显高于 M1a（WebView 投影、resize、FOV 缩放时每帧更新）。

推荐默认：**先 M1a 把光路模型做对，M2 再上天空投影和虚线目标框。** 若你认为「没有虚线目标就不像现在的产品」，则本期直接 M1b。

## 7. 偏好与迁移

现有键视为 **主镜** 的首套配置：

`star_map_fov_mode`、`star_map_telescope_id`、`star_map_eyepiece_`*、`star_map_sensor_*`、`star_map_custom_*`、`star_map_show_fov_overlay`。

新增：


| 键                       | 含义                      | 缺省                                     |
| ----------------------- | ----------------------- | -------------------------------------- |
| `star_map_active_train` | `primary` / `secondary` | `secondary`（导星+相机 GOTO 是本需求主场景）        |
| `star_map_secondary_*`  | 导星整套（与主镜同结构）            | 若有已连接相机则导星默认 `SENSOR` + 已连接相机；否则短焦目镜预设 |


`persistFovPrefs()` 仍然**不得**顺手覆盖 `plate_focal_length_mm`（已有设计）。只有用户在某条光路里明确选了望远镜焦距时才写入；写入时用**该光路**的焦距。

板解常用的是导星相机：若导星是 `SENSOR`，在导星 sheet 里选焦距时更新 `plate_focal_length_mm`；主镜目视改焦距不改板解焦距。请在第 9 节确认。

## 10. 验收（按第 9 节选定范围裁剪）

- 主镜、导星各有一套焦距 + 目镜或像面，互不覆盖。
- 主镜可选相机矩形，导星可选目镜圆形（交叉组合）。
- 切换后屏幕上只有一条光路的视场；不会出现「圆+矩」两套几何。
- 实线当前、虚线目标（若本期做虚线）共用该光路形状。
- 已连接相机仍可挂到任一条光路的传感器列表。
- 旧安装打开后主镜配置等于现在的那一套，不丢焦距。
- 跟随 / 拖动暂停跟随 / 居中到赤道仪行为不变。
- 单元测试锁：隐藏、只推激活光路、旧键迁移、交叉形状。
