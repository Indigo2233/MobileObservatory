## 1. 保留已有约定

| 项目 | 约定 |
|---|---|
| 光路 | 主镜 / 导星各有独立焦距和终端。主镜可以接相机，导星/寻星也可以用目镜；名称不限制终端类型 |
| 激活显示 | 同一时刻只显示激活光路的一组当前/目标视场，避免堆叠；默认导星，保留已有偏好 |
| 形状 | 目镜圆、相机矩；线型表示当前/目标角色，不表示终端种类 |
| 样式 | 当前绿实线、目标黄虚线，同一光路使用同一几何。角色色不等于到位质量认证 |
| 位置角 | 采用现有 WCS/传感器位置角约定和天球角点投影，保留马赛克及旋转器角度校准 |
| 设置 | 观测工具切激活光路，视场设置可编辑另一光路而不切显示；不新增第三个星图圆钮 |
| 标签 | 保留“主镜/导星”与“望远镜 + 终端”组合名；当前、目标、构图及指向来源不能混用 |
| 板解焦距 | 只有在导星且为相机时明确修改视场焦距，才写 `plate_focal_length_mm`；批量保存偏好不覆盖它 |
| 行为 | 切显示光路不改变目标、不发 GOTO/SYNC、不自动改变拍摄参数；真实参考源变更要显式选择并验证 |

现有 [StarMapOpticsTrain](../app/src/main/java/com/indigo/mobileobservatory/astro/StarMapOpticsTrain.kt) 表达视场配置，[SensorAngleCalibration](../app/src/main/java/com/indigo/mobileobservatory/astro/SensorAngleCalibration.kt) 表达像面/旋转器角度关系，都不能单独证明两条光路同轴或手机已对准镜筒。

## 2. 当前框、目标框与构图预览

当前代码在连接架台时使用其回读作为当前中心，未连接时使用屏幕中心；目标框在选中天体时投影到目标，否则取屏幕中心。这是现状，以下 WF-09 约定仍待实现：

| 情况 | 当前框 | 目标/构图框 |
|---|---|---|
| 有该光路的新鲜、合格光学观测 | 使用该光路的参考光轴方向；显示来源和有效状态 | 有选中目标则钉目标天空坐标 |
| 有有效安装关系与可用姿态传播 | 显示推算的镜筒方向，标明估计状态/年龄 | 同上；不因当前框靠近就直接确认到位 |
| 只有架台回读 | 可显示“架台估计”，不能称为已光学验证；所选光路关系未知时不能冒充其光轴 | 目标仍独立显示 |
| 只有未标定手机中心 | 可显示明确的手机方向标记，不作为镜筒当前框 | 引导补全手机到镜筒标定 |
| 没有有效当前指向 | 不画带“当前”含义的伪绿框；保留重新定位/校准入口 | 可继续浏览与构图 |
| 未选择目标 | 当前框是否存在取决于来源 | 在屏幕中心显示明确标为“构图”的预览，不暗示已选天体或望远镜已到位 |

拖动星图只改变画布，不改变上述天空锚点。跟随默认关闭，单指拖动暂停跟随；缩放不强制关闭，指向刷新不抢居中。没有有效指向时，跟随/居中操作解释缺失条件，不把画布中心写成实测坐标。

当前框样式与“目标已到位”状态分离。后者取决于新鲜验证、误差预算和目标是否落在有效视场内，详见指向方案。

## 3. 接入光路与校准关系（待实现）

- 工作光路决定“引导哪根镜筒”；显示用激活光路不隐式改写运行中任务。计划目标、执行目标与当前估计分别保存。
- 主镜相机中心需附实际光轴像素/ROI 定义；辅助相机必须有到主镜的有效关系，才能用其解算确认主镜到位。
- 手机偏轴安装用有效的完整姿态和镜筒轴关系换算；不能直接把手机 RA/Dec 放在主镜当前框上。
- 两条光路中心未知时不能默认同轴。先允许各自独立的视场规划，再按亮星/双解算建立关系；切换不会自动制造标定。
- 传感器滚转、旋转器零偏、辅助镜偏轴、手机安装关系分别管理。旋转器位置角已校准不能替代轴向标定。
- 来源切换、镜头/安装变更、解算过期按对应关系局部失效；标签、当前框和推镜引导同时更新，不出现一处称已到位另一处称未校准。

## 4. 偏好与兼容

旧 `star_map_fov_mode`、`star_map_telescope_id`、目镜/传感器及自定义键继续作为主镜配置；副光路沿用 `star_map_secondary_*`，激活显示沿用 `star_map_active_train`。现有安装的选择、设备库、位置角和马赛克设置不得在迁移时重置。

新增的标定、来源和质量数据另有版本与设备/光路身份，不从旧视场焦距或“已连接”标志推断。持久化安装关系不等于恢复上次“已到位”认证。序列相关入口继续遵守发布开关。
