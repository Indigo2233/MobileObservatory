# 太阳线扫第一实施批次

2026-11-27

本批次落实 [太阳线扫与自动重建技术方案](SOLAR_SCAN_RECONSTRUCTION_PLAN.md) 中可独立验收的手动重建、仿真采集、结果提交与回收站保留策略。真机双向扫描仍以设备标定和现场验收为前置条件。

## 已接入

- 拍摄页溢出菜单、工具页和 SER 素材操作提供「太阳线扫」入口，返回来源与现有页面导航共用。
- 手动重建可选择应用内 SER。谱线搜索、二次曲线拟合、有效列检查、ROI 推荐、谱线偏移重建、平场/扫描/盘面校正、构图和 PNG/FITS 编码均调用固定修订的 MJSol'Ex Rust 核心。
- 重建界面可设置条带方向、自动或手动参考宽度、扫描行对齐、支架周期性抖动、虚拟平场强度和应用内 SER 实拍平场。参数会在重建后保存，应用重启后继续加载；任务清单同时记录用户参数、每趟实际参数和 Rust 实际应用的校正。
- 输出支持显示 PNG、线性 PNG 和线性 16 位 FITS。所有产物先在暂存目录完成并校验，再以目录重命名提交。
- 任务清单记录源文件身份、实际帧数、谱线拟合、重建设置、方向、产物和原片处置状态。提交后的产物路径会随暂存目录重命名更新。
- 双向往返仿真按 A→B、B→A 交替生成带弯曲暗线和非对称盘面标记的 SER，重建后把 B→A 结果翻转到统一朝向。
- 扫描参数和重建设置写入应用偏好；已完成任务从原子清单恢复。页面切到其他工作区时保留任务入口和 STOP，应用退到后台时停止当前仿真处理。
- 启动时恢复已写清单的暂存结果，清理没有清单的残缺暂存目录，并继续完成提交后中断的原片处置。未提交的原始 SER 保留供检查，不会在重启时重复发布结果。
- 原片策略支持保留、提交后移入回收站和提交后删除。独占取得原片后核对文件身份和任务取消状态。
- 正常提交与重启补做共用原片处置入口。每趟必选产物在核对字节数和 SHA-256 之前取得租约，直至原片处置结束才释放。旧清单缺少摘要时读取 PNG/FITS 格式与尺寸。产物缺失、截断或内容变化，以及盘面覆盖不完整或加减速重叠时保留原片。
- 自动处置、重命名、移入回收站和到期清理共用按文件登记的媒体租约。FITS 序列首帧分享同时持有首帧和序列目录的租约。分享结果返回后租约再保留 15 分钟，覆盖外部接收方读取期间。
- 系统重建预算取 `ActivityManager.MemoryInfo` 的 `availMem - threshold`。读数缺失与有效的零余量分别传递；任务清单记录初始余量、首次采样时间、成功采样次数、最大采样间隔和盘面几何校正是否执行。
- Rust 在每个输出文件前后检查取消。Kotlin 在发布清单和处置原片前再次检查任务状态。自动处置任务在启动后台处理前建立恢复许可，提交结果时沿用该许可。STOP 入口先撤销许可，再请求后台协程取消。后台处理随后在清单记录已完成的处置和其余原片的保留状态。缺少许可的任务保留原片。
- 仿真 SER 先写入隐藏的 `.ser.partial`。整趟生成成功后改为隐藏的 `.ser.sealed`，按最终文件名计算身份，再原子发布到素材目录。重建清单保存这份身份。封口重命名失败时，在应用私有存储记录完成标记供启动恢复。缺少标记且仍有完整时间戳尾部的 partial 保留在原路径，等待人工检查。快速切换源 SER 会取消旧预览并校验最新选择。
- MJSol'Ex 的 Android GUI 作为独立 Cargo 特性构建。`patches/mjsolex-core-only.patch` 由 Gradle 幂等应用，太阳线扫 JNI 关闭该特性，避免 eframe/winit/egui 和上游 Android Activity 被链接进 APK。
- 手动重建和仿真往复在访问任务文件前等待启动维护完成。启动维护包括遗留 partial 清理、暂存恢复和待处置核对。
- 预览请求使用单调代次，文件与代次在同一次状态更新中核对。编辑中的重建参数保持为草稿，只有通过预检并开始手动重建或往复任务时才写入“上次实际使用”偏好。
- 回收站时间戳在文件移入前写入，进程在移动与标记之间中断时可安全重试；后台到期清理会跳过仍持有媒体租约或打开文件描述符的条目。
- 回收站条目首次移入时记录 `trashedAtUtc`。WorkManager 每日巡检并执行应用启动时的一次性清理，仅删除已满七天的带时间条目。旧条目缺少时间时保留。

## 验收边界

- 本轮自动化覆盖参数预检、盘外余量、扫描运动曲线、仿真 SER、谱线识别、重建产物、原子提交路径和回收站清理。
- 回归还覆盖结果缺失、截断或摘要变化时保留原片、完整产物正常处置、受阻原片在重启后继续复核、取消后保留首个封口 SER、零内存余量不被当成缺失、物理平场参数进入 Rust、导出首个产物后取消、仿真弦长沿空间轴增减、观察者异常的 JNI 调用顺序、旧预览代次不能覆盖新选择、重建草稿只在开始时写入上次使用值、媒体租约与独占处置的两种并发顺序、启动维护期间创建任务会等待、后台清理保留占用条目，以及 hidden partial 的启动清理和原子发布。
- 真实相机录制、真实赤道仪换向、停稳、全局 STOP、断电或断连恢复尚需选定设备后实机标定。界面将当前自动任务明确标为仿真验收任务，不把仿真结果作为硬件验收证据。
- MJSol'Ex 以 [固定提交 `2b047d9`](../app/src/main/rust/mjsolex) 的子模块集成，JNI 薄层位于 [solar_scan](../app/src/main/rust/solar_scan)。Kotlin 不再实现谱线拟合或 SER 重建，只负责调用、取消、进度、清单、原片处置与媒体归档。同源实拍 SER 与 MJSol'Ex 桌面版的逐像素对照仍待取得现场样本后完成。
- 并行录制与重建、后台持续任务和长时内存/温度验收未启用；当前仿真任务串行执行并遵守待处理上限的简单形式。
