## 优先约定：交互属于功能完成条件

新功能或入口先写清用户任务、唯一归属、当前对象/上下文、主操作、前置条件、返回和失败恢复。所有页面采用 IG-01–IG-10 的共同规则，先完成返回、设备就地控制、分类与任务衔接，再扩大入口；设备安全、崩溃、数据与科学正确性修复可先行。

一级结构为 **星图 / 拍摄 / 影像 / 器材** 四个任务工作区，并按用户要求保留 **工具** 集中快捷页；工具入口复用相同任务与返回路径。2026-10-14 已有基线原型并迁移主要代码；真人找入口和现场验收仍待完成。赤道仪完整控制归器材，常用控制在星图/顶部状态带就近可达。拍摄沿用现相机起始页，保持暗色/红光与自适应布局。

常规流程按“工作区 → 对象/任务 → 详细设置”三层预算；设备快捷控制一次打开，保存结果一次查看。预算不省略必要校准、确认和质量检查。共同交互、源码实现和真机验收分别记状态；仅有页面或说明文字不算整条任务已完成。细则、例外和 PR 最小记录以 [交互规范](INTERACTION_GUIDELINES.md) 为准。

## 极轴采样的相机所有权（2026-10-26）

极轴试拍、三点采样、单点重拍和调整测量共用任务内的单帧采集入口。顺序为停止原预览采集、确认相机停止、应用曝光、拍摄一帧、确认停止、保存 FITS 和解析；自动流程在解析成功、转轴到位并稳定后才请求下一帧。连续调整逐次执行曝光与解析，解析期间相机空闲。完成、失败或取消后保留暂停状态，返回拍摄页由用户恢复预览。

Player One 使用 SDK 原生单次曝光 `startExposure(true)`，触发前清空旧队列，保留本次首帧。其余适配器使用有界流式兼容路径；存在启动边界帧的适配器仅将该帧用于实时预览，单次采样等待符合采集要求的完整帧后停止，该路径可能包含额外的硬件曝光。任何停止失败均阻止本次图像进入解析及后续转轴。录制、录制收尾、实时叠加和设置写入占用时拒绝采样；单帧采集期间禁止恢复预览或修改拍摄设置。FITS 观测时刻按帧接收时间减实际曝光估算，SDK 停止及文件写入耗时不计入曝光时刻。硬件时序与 OnStep USB 到位行为继续按现场验收记录，见 [极轴诊断](POLAR_ALIGNMENT_DIAGNOSTICS.md)。

## 极轴与相机共用显示处理（2026-10-26）

2026-10-28 现场反馈更新：定位/极轴预览默认启用黑白显示；极轴可就地切回彩色。黑白转换在共享渲染器完成去马赛克和显示处理后执行，1:1 与缩略图使用相同设置。原始 FITS 的 Bayer 排列、位深和科学像素保留；页面明确列出解析原图格式，出现 2×2 求和重试时另行标明。此开关取代下段原先不增加极轴显示选项的约定。

2026-10-31 界面精简：原图格式和求和输入信息收至诊断区，主区保留图像、当前状态、错误及操作。高级设置采用成对字段，大字体改为单列；展开设置时压缩预览，详细计算结果归采样详情。GOTO 解析期间的停止同时覆盖新建进程尚未进入等待协程的取消时机，验证见 [极轴诊断](POLAR_ALIGNMENT_DIAGNOSTICS.md)。

极轴图像统一使用相机预览的 `FrameProcessor` 和当前 `CameraPreviewSettings`，复用自动拉伸、黑白点、白平衡、去马赛克及 LP700；极轴页不另设显示调节参数。FITS 文件适配只读取有界原始帧或复用相册已有的 UInt16 区域平均，保留位深与 CFA 相位，原始 FITS 和解析输入不受显示处理影响。缩略图由同一预览缩小，1:1 区域沿用主图的黑白点与 LP700 自动颜色、背景校正结果，并读取去马赛克所需邻域。保存图使用独立渲染实例和一张位图，避免与实时预览争用可变缓存。

## 极轴图像来源（2026-10-26）

各采样点的“选择”打开应用相册，复用媒体索引列出已拍摄及导入的 FIT/FITS、JPG/PNG，并展开 FITS 连拍组内的单帧；可按文件名或拍摄会话搜索。同一面板提供系统文件入口，取消系统选择回到相册，关闭相册保留原采样点和结果。选中后沿用现有缓存导入与预览流程，保留原始字节、FITS 时间头及可用的源文件修改时间。导入期间纳入停止/返回处理，并限制并发拍摄和解析。成功替换前三个采样点会清除相应极轴计算结果；选择新的修正图像保留已建立的三点校准。

## ASTAP 解算结果的身份与成功判定（2026-10-26）

每次解算通过 ASTAP `-o` 将 `.ini` 与 `.wcs` 输出到新建的专属缓存目录；原始图像直接作为输入，不增加图像副本或像素缓冲。结果读取仅限本次指定的两个输出文件，成功要求进程退出码为 0、本次 `.ini` 明确为 `PLTSOLVD=T`，且有可解析的有效天球坐标。显式 `PLTSOLVD=F` 的文件拒绝解析；已有 FITS 头、其他图像的解算结果和同一图像上一次的输出均不能作为本次成功的依据。成功时优先使用本次 `.wcs`，保留完整图像几何供极轴修正与指向校准使用。

日志记录独立输出前缀、退出码、`PLTSOLVD` 与最终 `solutionSource`；失败时来源为 `none`，极轴采样保留图像并进入解析失败状态。现场记录中的旧误报采样与其极轴误差需要重新解算、计算。

8 位单平面 FITS 因星数不足失败时，共享 ASTAP 入口自动尝试一次 2×2 原始像素求和，按 UInt16 保存 0–1020 的完整和，并固定 ASTAP 内部合并为 1。2026-10-31 扩展至标准 UInt16 输入，以 Int32 保存 0–262140 的完整和。处理按两行流式进行，保持原图与物理视场；奇数尺寸、缩放数据及其他格式沿用原处理结果。成功 WCS 按 `p_original = 2*p_sum − 0.5` 恢复原图参考像素、CD/CDELT 与 SIP 系数，再供单张解析、极轴和指向任务使用；临时求和图在结束或取消后清理。原图及预览参数独立于此解算重试，重试仍须通过退出码和当前输出成功标志检查。停止入口、拍摄前稳定检查、Player One 单次曝光就绪等待与验证范围见 [极轴诊断](POLAR_ALIGNMENT_DIAGNOSTICS.md) 的 2026-10-31 记录。

## 拍摄竖屏与模拟相机（2026-10-15）

用户确认参数条与临时面板方案后，按本节实现并构建测试 APK，提交独立正式 PR；合并和发布仍以仓库实际状态为准。

- 红光使用顶部全局入口，拍摄预览的省略号去掉重复开关。
- 拍摄允许横竖屏。竖屏预览默认优先铺满可用宽度，高度按当前 ROI 和旋转后的图像比例确定；打开参数面板不得缩小图像宽度。下方改为“曝光 / 增益 / 拉伸 / 拍摄设置”参数条，读数可直接点按；一次只显示当前调节面板，可关闭或下拉收起，不把整个页面展开成长表。拍摄设置仅列拍摄、图像、裁切，设备信息和连接仍走顶部设备入口。面板内保留录制停止和架台 STOP。横屏保留右侧控制面板。两种方向复用预览和完整控制节点、同一 ViewModel；格式和限额在竖屏用紧凑菜单，目标仍从顶部选择。
- 未连接相机时可手动“试用模拟相机”，也可从预览菜单进入；模拟模式有常驻标记和退出操作，不自动启用、不替换正在连接或已连接的真实相机。该来源支持合成星场预览、曝光/增益、ROI、格式切换和暂停。拍照/录像仅演示状态与计数，不保存文件；不提供科学采集来源，不参与实拍校准证据。虚拟预览采用加速帧率，不代表实际曝光时序。
- 系统返回优先关闭当前参数面板或省略号菜单；输入时先遵循系统收起键盘。面板为系统导航栏留白，大字体下内容可滚动，关闭与停止操作留在标题区。拍摄格式和限额在窄屏/大字体下可横向滚动。
- 模拟相机用三个固定缓冲区交付预览，消费者归还前不覆盖；停止、重启与退出使旧采集失效。演示录像仅更新计数和限额，不进入真实录像队列，也不生成校准来源或科学曝光记录。旋转复用当前相机会话和设置。自动化与实际设备验收分开记录，见 [TODO](../TODO.md)。

## 拍摄页紧凑布局与预览菜单（2026-10-16）

拍摄页采用单层工作画面：全局设备状态带压缩高度；旧第二顶栏移除。预览菜单承载 CFA、叠加层、对焦辅助、中心标记、实时叠加、选择观测目标、解析当前帧和 LP700 预览映射。夜间红光由全局状态带管理，文件浏览归影像工作区，普通离线图像解析归影像/工具工作区。

连接成功由顶部设备状态带表达，预览不重复显示相机名称或序列号。拍摄底栏保持紧凑；目标使用下拉选择，与单张格式、录像格式和录像限制同排；拍照及录像按钮采用 48dp 尺寸。横屏右侧控制栏宽度为 280dp，顶部曝光、增益、制冷和帧率采用小字号单行摘要。整数毫秒省略小数部分，底层曝光值继续使用浮点微秒。BIN 只在裁切/ROI 栏目显示。

“解析当前帧”首次使用先填写并持久化焦距，再保存当前科学帧为临时 FITS 并进入解析结果页自动开始。LP700 开关默认关闭，仅对 Bayer 预览生效；说明展示处理边界、作者“奎木娘HIP5447”及可直接打开的 B 站主页。该开关只控制显示处理，不修改 FITS、标定数据或科学叠加结果。

## FITS 按文件分享（2026-10-26）

FIT/FITS 通过分享请求、`ClipData` 和文件 URI 类型统一声明为 `application/octet-stream`，接收软件按通用附件处理。包含 FITS 的多选也使用文件分享类型，保持原始文件名、扩展名和字节内容，并仅授予临时读取权限。JPEG/PNG、MP4、ZIP、日志和 APK 更新继续使用各自已有类型；文件入口及授权目录沿用现有配置。

## 实时与后期叠加

2026-10-19：后期导入先提供有界全视野预览，叠加范围改为真正的文件裁切，并加入处理 Bin 1–4；默认保留原范围和 Bin 1，预算不足时优先给出保留视野的 Bin 建议，也可明确选择建议裁切。原始分块像素依次校准、去马赛克、软件 Bin 后才进入叠加，预览像素不参与计算。取消固定 256 MiB 封顶，按实际应用堆上限的 40% 计算；预计工作集、叠加预算与手机总 RAM 不混称。实时与后期使用符合各自数组并存关系的估算，详情折叠。见 [分块处理与预算](STACKING_CALIBRATION.md#tiled-offline-processing-and-heap-budgets-2026-10-19)。

2026-10-18：叠加不再按统一 419 万像素拒绝，改按通道、算法、Bin、校准和工作集预算判断，仍保留图像表示/单帧字节上限。拍摄设置的“裁切区域”与实时叠加共用“叠加范围”：显示当前框、建议最大虚线框、输入/输出尺寸；选择原比例/1:1/4:3/16:9，点图移动，点击后才写入相机。预算细节收在“为什么有限制？”，旧裁切预设/滑块收在“手动裁切”。录制、叠加和校准状态会限制应用动作并给出原因；没有自动裁切、改 Bin 或清空校准。详细来源、估算及边界见 [叠加预算与 ROI](STACKING_CALIBRATION.md#adaptive-roi-planning-2026-10-18)。

2026-10-14 按用户补充统一入口：拍摄及预览工具里的「实时叠加」，影像首页「导入影像」旁独立的「后期叠加」。两个工作流都在顶部用「行星 / 深空」标签选择对象；导入只负责把外部文件加入同一媒体库。录像列表/播放器的就近叠加入口仍打开同一后期任务。叠加独立于序列开关，后期不要求连接设备。

实时默认深空，后期默认行星，两者分别保留选择和处理配方。已有未保存结果、分析或运行任务时，切换对象需明确重置；保留原始文件和已导出文件，不能把一种配准的旧累计用于另一种。当前后期叠加支持 SER/PSER；媒体导入支持 SER/PSER、FITS、JPG/PNG，并不意味着所有媒体格式均可科学叠加。

## 星图：视场框样式

两条光路（主镜 / 导星），同一时刻只画**激活那一条**的视场。两框同一形状：绿实线 = 当前，黄虚线 = 目标。

| 点 | 约定 |
|---|---|
| 光路 | 各有焦距 + 终端（目镜圆或相机矩），互不覆盖。默认显示**导星**。 |
| 当前框 | `#fov-current`，优先使用激活光路的有效定位与实测位置角；仅有架台回读时标“当前参考 · 架台估计”。光学几何未确认时采用配置视场并标“当前参考”；相机角度未知时标“北向上 · 角度未测”，位置角为 0°。该参考不验证光路关系或裁切覆盖范围。架台断线、读取能力撤销或坐标失效时清除其参考框。无来源时不以画布中心制造当前指向。 |
| 目标框 | `#fov-target`，黄虚线。选中目标后钉在目标 RA/Dec；未选目标时在画布中心显示“仅供构图”。计划位置角独立于当前框，不作为当前相机实测角度。 |
| 传感器位置角 | 与 NINA/WCS 一致，从天球北向经东向计量。矩形长边在位置角 `0°` 时与目标处赤纬线相切。传感器单框和马赛克从共同切平面计算天球四角，再逐角投影到当前星图；地平视图、天极附近、超广角和星图移动时实时重算。 |
| 马赛克 | 相机模式提供 `1..10` 行、`1..10` 列、`0..90%` 重叠率、位置角和面板编号。执行顺序支持逐行、蛇形、逐列及四个起始角，默认从左上角蛇形移动。设置写入 `star_map_mosaic_*` 偏好。 |
| 构图导入序列 | 星图按共同切平面计算每个面板中心，简单序列保存可启停、重排和单独重拍的面板列表；高级序列生成独立目标、面板元数据、指向、居中和曝光指令。再次导入同名马赛克时更新高级序列中的原面板。 |
| 解算角度 | WCS 解算结果统一换算为传感器位置角。星图可采用解算角度、显示计划误差，并以当前机械角校准旋转器偏移和方向。连接旋转器时可直接转到构图角度。 |
| 渲染刷新 | 引擎属性变化可能早于 VIEW 矩阵更新；视场在下一渲染帧完成后统一重画，避免旧矩阵结果因缓存保留在屏幕外。当前框与目标框共用该刷新调度。 |
| 标签 | 光路切换始终写「主镜」「导星」，设备自定义名不替换这两个字。视场框/圈显示 **望远镜 + 终端** 组合名，例如 `C8 + 25 mm · 50° 当前 1.50°` / `C8 + ASI533 目标 1.20°×0.80°`。 |

## 赤道仪：全局 STOP 与手动方向键

同一时刻只允许一种运动（`MountMotionRunner`）。GOTO、回零、定距 RA 期间显示全局 STOP。

**手动方向键（按住移动、松手停止）不弹全局 STOP。** 方向盘里已经有停止键。弹窗与左下角方向盘重叠，新窗口一出现会取消当前按住，表现为「按钮被顶上去、断触」。

星图在 GOTO / 回零 / 定距 RA 时**独占底栏 STOP**：收起观测工具、星图图层和目标卡，STOP 常驻底栏中央且不随浮层自动隐藏。其它页仍用左下角 Popup。

普通 GOTO 的 STOP **只在赤道仪真的在转时出现**。一开始就停着（包括已经在目标附近、固件不再转动）不显示 STOP，安静几拍后结束这次 GOTO。高速转动停下后 STOP 收起，不要求回报坐标进到 3′。指向并居中在整段过程里保留 STOP，因为中间还有拍照和解算。

指向并居中的运行状态条同时提供查看进度；关闭面板后可从这里恢复查看当前任务。查看进度与 STOP 分开，不受目标卡或星图普通控件的隐藏影响。

赤道仪页的速率芯片是**手动方向键**速度，不是跟踪。跟踪单独一排：停止、恒星、月球、太阳。停止发送 `:Td#`（OnStep）或对应协议的停跟踪，并读掉应答，避免串口里留下一个字节。

拍摄预览提供紧凑方向控制：四个方向箭头围绕速度下拉按钮，普通字号约 144 × 144 dp，触控区域各为 48 dp。新连接赤道仪后默认显示，拍摄预览三点菜单中的赤道仪方向控制可切换显示；同一连接中保留用户选择。控件使用共享手动移动和速度状态，按住移动，松手、取消、隐藏或页面失去前台时停止当前按住动作。自动运动及只读连接禁用方向和速度选择。对焦辅助开启时调整控件位置并限制对焦浮层宽度，为方向按钮留出空间；短预览窗下将方向控件移到左侧，避开右上工具栏。常规回归通过控件状态与真实按压验证，截图仅在必要时单独采集。

跟踪状态采用设备读回，包含开启、关闭和未知。连接完成、GOTO 到达、回零位完成、RA 移动结束及停止操作后刷新；空闲期间持续读取，反映手控器等外部控制源的变化。未知状态不选中停止芯片。连接本身只观察跟踪状态。

自动三点对极轴在首张曝光及 RA 移动前检查跟踪；GOTO 到达后同样检查。确认关闭时发送一次开启命令，然后独立读回确认；读回仍关闭或已支持的查询失败时结束该动作并显示错误。回零位后读取实际状态；通过普通 GOTO 实现回零位的适配器在到达后停止跟踪。应用开启跟踪的所有权独立记录，只读切换保留设备原先自行开启的跟踪。协议依据与回归记录见 [跟踪状态诊断](MOUNT_TRACKING_DIAGNOSTICS.md)。

| `MountMotionType` | 全局 STOP |
|---|---|
| `GOTO` / `HOME` / `RA_MOVE` | 显示 |
| `MANUAL` | 不显示（`showsGlobalStop == false`） |
| `IDLE` | 不显示 |

星图方向盘在南键下提供「回零位」（先确认）。赤道仪页与相机侧栏同样有回零 / 重设零位。

**代码：** `MountMotionState.showsGlobalStop`、`MountMotionStopBanner`、`CameraScreen.MountMotionStopPopup`、`StarMapScreen`

## 赤道仪：连接时同步时间

USB、TCP、蓝牙及 SynScan Wi-Fi 使用统一的连接收尾流程：支持时间写入的连接从手机同步日期、时间和时区，再回读校验，误差超过 10 秒时显示失败原因；只读连接仅查询时间，不支持时间的协议跳过。同步失败保留实际连接状态，清空未经确认的时间，并提示检查日期、时区和观测位置。观测位置沿用既有同步入口。

OnStep 的 `:SG` 偏移表示 UTC 减本地时间，例如 UTC+8 写入 `:SG-08#`。其 `:SG`、`:SC`、`:SL` 应答按单字节读取；读取时间时同时读取 `:GG#`，使用赤道仪的偏移换算 UTC。手动时间同步也必须回读校验。

**回归：** `OnStepClockTest`、`MountClockConnectionInstrumentedTest`、`MountReadOnlyLoopbackTest`。

## 板解：焦距、像元与视场

用户不要手填视场高度。界面是 **焦距 + 像元（或选传感器）**，再算出 ASTAP 所需 FOV。

| 点 | 约定 |
|---|---|
| JPG / PNG | 没有 FITS `FOVH`。用 `206.265 × 像元μm / 焦距mm` 得角秒/像素，再乘图像高度。 |
| ASTAP `-fov` | 非 FITS 时是**图像高度（度）**，不是对角线、也不是宽度。 |
| 用户填的焦距 | 解算输入以用户当前值为准，不得用上一次解出的 525 mm 之类结果粘住下一次。 |
| 解算后 | 可显示**实测焦距**（由 ″/px 反推），那是结果，不是下次输入。 |
| 传感器目录 | 用画幅区分相近像元（如 IMX455 vs IMX571）。 |
| 星图 | `persistFovPrefs()` 不得覆盖 `plate_focal_length_mm`。只有在**导星且为相机**的视场设置里明确改焦距时才写入。 |

**代码：** `PlateSolveOptics.kt`、`SolveOpticsFields.kt`、`OpticsEquipment.defaultSensors`、`FitsSolveHints.kt`、极轴页同一套光学栏

## 指向并居中：历元与停止误差

应用统一的赤道仪坐标接口与星图点击用 **JNOW**；星图目录和 ASTAP WCS 用 **J2000/ICRF**。具体线协议由适配器转换，例如 SynScan 手控器路径的 J2000，不能把所有设备回读直接标成 JNOW。混用历元会产生足以影响 6′ 停止条件的偏差。

| 点 | 约定 |
|---|---|
| 进赤道仪前 | `EquatorialEpoch.toJnowHours`：J2000/ICRF 岁差到当日，JNOW 原样。GOTO / 同步 / 指向并居中共用。 |
| ASTAP 结果 | CRVAL 是 J2000，先转到 JNOW 再和目标比、再 sync。 |
| 星图居中 | 解算坐标已经是 JNOW，`centerOnRaDec(..., frame = "JNOW")`。 |
| 停止误差 | 默认 **6′**。星图「观测工具」可改，写入 `star_map_precision_tolerance_arcmin`，范围 1′–30′。 |
| 成功当轮 | 若赤道仪支持 sync，仍要把解算位置 sync 上去，避免第一轮已够近却模型不更新。 |

**代码：** `EquatorialEpoch.kt`、`PrecisionGotoMath`、`CameraViewModel.startPrecisionGoto`、`StarMapHud` 观测工具面板

**回归：** `EquatorialEpochTest`、`PrecisionGotoMathTest`、`ObservingUiWiringTest.precisionGotoUnifiesEpochsAndExposesSixArcminTolerance`

## 图谱（ToupTek）USB 连接

图谱 SDK 用 Android 已经打开的 fd（`Toupcam_Open("fd-%d-%04x-%04x")`），自己不走 libusb。

- 打开后必须把 `UsbDeviceConnection` 保存在 Java 里，直到主动断开。丢掉引用后 GC 会关 fd，表现为连不上或连上立刻掉线。ZWO / QHY / 图谱滤镜轮都是这样持有的。句柄要在 `Toupcam_Open` 返回前就赋给字段。
- 枚举结束不要把连接状态设成 `Enumerating`。那个状态会用转圈盖住连接按钮，而且没有超时和报错。USB 权限弹窗必须在主线程申请；打开相机不要在 `open()` 里写 binning。
- 扫描只按 Android USB 列表列出相机，不要在扫描时启动 Player One SDK。点中某一台后才连接，Player One 的 SDK 只在这时启动。
- 导星相机不打开主相机已经占用的那台 USB 设备。主相机没连接时，导星相机可以单独连接，例如主镜目视、导星镜负责指向。拔掉其中一台时，另一个会话不要跟着断开。
- 有线 OnStep 先在 DTR/RTS 拉低时轮询 `:GR#`，不要一连接就翻转 DTR。翻转会复位控制板，断开后立刻重连就会在启动完成前失败。断开必须等串口关完，再开始下一次打开。
- SDK 型号表没有的 PID 仍当作相机列出，不要因为 `getModelName` 为空就忽略。消费版 VID 不只是 `0x0547`：USB2/Cypress 是 `0x04B4`，部分 GPM/OEM 462 在 Android 上报 USB3 Vision 通用号 `0x2BA2`。工业 overlay 的 `0x2BA2` 仍走 Galaxy，只用 `isProtocolVendor`。
- 预览降采样只发生在 `FrameProcessor.frameToBitmap`，且仅当帧超过约 4MP；拍摄/FITS 走原图。常见图谱行星相机尺寸应保持 `sampleStep = 1`。
- 工业 overlay 覆盖 `DahengCameraManager.kt` 时必须带上 USB 句柄持有和未知 PID 枚举，否则会把公有树修复盖掉。

**代码：** `DahengCameraManager.openToupcamDevice`、`ToupTekDevices`

**回归：** `ObservingUiWiringTest.toupTekCameraKeepsTheUsbConnectionAlive`、`previewDownsampleIsDisplayOnly`、`PreviewScaleTest.typicalToupTekPreviewSizesStayFullResolution`、`ToupTekDevicesTest`

## 序列：参数密度与展开操作

手机竖屏上的序列参数按内容长度排布。数值和短表达式在可用宽度不少于 300 dp 时每行放两个；路径、批注、条件表达式和选择芯片占整行。深层嵌套导致可用宽度变窄时自动恢复单列，避免输入内容和标签被压缩。

点击指令标题展开参数，再次点击同一标题直接收起。点击另一条指令时收起原指令并展开新指令。

拖动指令时，编辑区域最右侧显示固定删除区。指令进入删除区后停止边缘自动滚动，松手完成删除；删除区覆盖在编辑器上方，不改变序列列表的可用高度。

开始、目标、结束三区只承载普通指令，不显示或接受触发器与循环条件。根节点只承载全局触发器。触发器和循环条件入口显示在 NINA 支持这些集合的目标及顺序指令集内。
