# 靛空台太阳线扫与自动重建技术方案

2026-11-27 · 设计稿 · 算法基线 MJSol'Ex v0.0.3（`2b047d9`）

## 1. 目标与范围

在靛空台中完成太阳光谱的采集、重建和结果归档。用户在「拍摄 → 太阳线扫」指明两个扫描端点及重建参数，应用按 A→B、B→A 交替扫描。每个方向生成一段独立 SER 和一组重建图。结果保存并通过校验后，应用按本次任务选定的策略保留原片、移入回收站或直接删除。移入回收站的原片从入站时起保留 7 天。

首版支持前台运行和一款已通过双向扫速验收的赤道仪。用户先用预览确认太阳光谱、狭缝方向和两端留白，再启动任务。任务支持指定趟数或持续扫描。持续扫描受设备连接、运动范围与剩余空间约束。前台内切换页面时保留任务及全局 STOP。应用退至后台或设备断开时进入停止流程。进程重启后可以恢复文件处理，运动从用户确认的新一轮开始。

Kotlin 负责相机、赤道仪、任务状态、持久化、结果入库与原片处置。Rust 负责 SER 解码、谱线定位、图像重建、校准和产物编码。两端的职责以一个已写完的 SER 文件为交接点。素材库手动重建和自动扫描使用同一个重建执行器。

## 3. 用户流程与任务状态

### 配置

- 从「拍摄 → 太阳线扫」启用自动采集。在素材库选中 SER 时提供「线扫重建」，进入同一套谱线、校准与输出设置。
- 拍摄页显示光谱预览、「找谱线 ROI」、谱线预设或取样位置、扫速档位、曝光、实测帧率、两端留白、趟数和剩余空间。根据镜头朝向和扫描方向预设结果朝向。平场、色散、扫描伪影校正及其他输出选项放在高级设置。
- 默认保存可查看的拉伸 PNG 和保留线性强度的 FITS。其余产物按用户选择生成。原片默认保留。「移入回收站」和「保存后直接删除」由用户在开始任务前选择，确认后的策略随任务记录保存。
- 运行中显示当前方向、已完成趟数、待重建数和最近结果。全局 STOP 始终可达。正常结束支持「完成当前趟后结束」，急停优先停止运动并关闭当前录制。

### 单趟执行

```text
检查空间、设备和运动范围
    → 到达起点并确认稳定
    → 开始 SER 录制并确认首帧入队
    → 在盘外加速并确认进入稳定扫速
    → 恒速经过入盘前天空、日面和出盘后天空
    → 在盘外减速，到达终点并停稳，封口 SER
    → 保存完成记录并入重建队列
    → 检查是否允许从终点开始下一趟
```

首版使用用户在预览中确认的端点和该机型实测余量。预览通过后保存实际采集设置，并在整轮任务中锁定。断开或重新打开设备后重新校验。

采集和重建分别记录状态。采集记录包含「录制中、正在封口、已封口、中止或失败」。重建记录包含「待处理、处理中、结果已提交、原片已处置、失败待处理」。处置失败有独立状态，已提交结果仍可查看。两套状态通过趟号关联，UI 重建或进程重启后可从本地记录恢复。

## 4. 往复运动、扫速和曝光

### 4.1 16× 实拍起点与双向标定

2026-11-27 实拍记录中，赤道仪使用 **16×** 档位，每趟约 **6 秒**，可作为当前设备组合的初始试扫设置。靛空台已有该速率档位。现场分别记录完整 A→B 或 B→A 用时与有效穿盘用时，再单独记录停稳和重建用时。任务根据端点、运动状态及超时条件结束一趟。 [速率档位](../app/src/main/java/com/indigo/mobileobservatory/mount/Lx200MountController.kt#L126)

- 复用 `MountMotionRunner` 独占赤道仪运动。扫描期间暂停导星脉冲，避免手动方向键、GOTO 和其他任务争用运动通道。开始时保存跟踪模式和速率档位，正常结束后按设备状态恢复。 [运动互斥](../app/src/main/java/com/indigo/mobileobservatory/mount/MountMotionRunner.kt#L53)
- 把赤经运动投影到以太阳为中心的局部天球平面。计算赤经差时处理跨 0 时环绕和赤纬投影，并将运动投影到垂直狭缝的方向。太阳相对狭缝的实际扫速取自标定和运行测量。分别测量 A→B 与 B→A，以覆盖跟踪方向、换向回差和不同协议对速率的影响。
- 两端盘外余量以预览或试扫确认的太阳边缘为基准，按两个方向分别估算。A 和 B 每个端点都承担一趟的起点和另一趟的终点，取两种用途所需余量的较大值。用户确认端点及运动范围后开始连续扫描。
- 每趟保留命令时刻、坐标与速度样本、首末帧时间、实际帧数和丢帧数。SER 现有时间戳在写入时取得。采集编排应另记帧序号、适配器可用的采集时间和手机单调时钟上的接收时间，并与支架事件对齐。只有具备足够时间和位置精度时，才据此截取有效帧或校正扫速波动。现有约 500 ms 的坐标轮询可用于粗略确认位置。端点余量须覆盖该轮询和停止命令带来的最坏位置误差。 [当前时间戳](../app/src/main/java/com/indigo/mobileobservatory/recording/SERWriter.kt#L111)

### 4.2 两端越过太阳边缘

| 阶段 | 运动与采集准则 |
| --- | --- |
| 起点等待 | 起点位于盘外。赤道仪停稳后启动录制，确认收到首帧，然后发出扫描运动命令。 |
| 加速与消除回差 | 在盘外完成启动、反向回差和加速。试扫测得从运动命令到速度进入并保持在允许范围内的距离。正式采集时，在狭缝接触太阳边缘前确认或通过已验证的标定约束进入有效扫速。 |
| 恒速扫掠 | 用稳定速度获取进入日面前的天空、整个太阳盘以及离开太阳盘后的天空。盘外留白按所需天空背景和日珥视场确定。 |
| 减速与换向 | 完全扫出日面并保留所需盘外帧后，才开始减速。确认终点停稳、完成本趟 SER 封口，再按调度策略开始反向扫描。 |

起点所需盘外距离由 **启动及加速距离 + 入盘前稳定留白 + 位置不确定余量** 构成。终点所需盘外距离由 **出盘后稳定留白 + 减速到停止的距离 + 位置不确定余量** 构成。余量按实测值设定，覆盖命令与读回延迟以及盘缘定位误差。试扫记录每个方向的这三段距离和阶段时刻。

SER 保留整趟录制。重建使用有可靠依据的稳定区间，同时保留整盘和两端需要的盘外帧。稳定区间无法可靠定位时，结合试扫标定和帧内容判断覆盖。检测到加减速区进入太阳盘、有效日面被裁切或覆盖无法确认时，该趟标记待检查并保留原片。

每趟设最大运动时间和允许坐标范围。坐标读回异常、未按预期方向移动、相机断开或写入失败时，启动停止及封口流程。停止命令发出后等待设备确认或读回停稳。无法确认时，UI 显示「停止未确认」并禁止下一趟。App 退出时尽力停机，后续无人值守能力需要支架端已验证的停机保障。

原始 SER 保持采集顺序。按实际方向使用 `Framing.flip_y` 合并用户的方向设置，统一往返成图。左右镜像和旋转依光学安装设置。线芯、正负偏移及双翼产物共用同一方向变换。 [构图参数](https://github.com/Indigo2233/mjsolex-rs/blob/v0.0.3/src/framing.rs#L4)

### 4.3 曝光、帧率和采样

| 量 | 计算或测量方式 |
| --- | --- |
| 每帧扫过的角距离 | 垂直狭缝的实际扫速 ÷ 持续写入 SER 的实测帧率。用实际帧间隔评估跳帧和采样空缺。 |
| 单帧运动模糊 | 垂直狭缝的实际扫速 × 相机实际曝光时间。 |
| 建议曝光上限 | 允许的扫掠模糊角宽 ÷ 实测扫速。用光学像尺度及目标采样确定允许角宽。参数未知时显示试扫帧率和帧数，并保留手动曝光。 |

例如，若实测有效穿盘为 6 秒，目标是取得 1200 行有效重建数据，则相机到 SER 的有效写入帧率约需 200 FPS。曝光、读出、USB 传输和手机写入共同限制实际帧率。在预览中调窄 ROI 后实测写入帧率，并检查线芯信号和谱翼高光。由用户确认曝光和增益，整个往复任务锁定曝光、增益、ROI、原始像素格式及校准设置。降低帧率或出现掉帧时，提示其对采样间隔的影响，并允许调整扫速、ROI 或曝光后重新试扫。 [相机接口](../app/src/main/java/com/indigo/mobileobservatory/camera/Camera.kt#L24)

完整扫描的质量判定包括帧数与文件长度匹配、谱线定位成功、两端有盘外余量且整盘拟合可信、有效采样无超过验收阈值的空缺、采集设置一致以及该趟未被中途停止。重建执行器区分普通提示和影响必选产物或覆盖质量的失败。能生成预览的异常趟可供检查，原片继续保留。

## 5. 谱线 ROI 辅助

### 5.1 找到暗线并推荐裁切

1. 用户点击「找谱线 ROI」。应用从较高的预览 ROI 获取一小组有太阳信号的原始光谱帧，并在光谱坐标中求稳健平均。显示预设谱线或用户点击的一处暗线作为搜索起点。候选暗线以相对两翼的吸收深度、沿狭缝的连续性和拟合残差评分。多条候选难以区分时显示位置供用户选择。
2. 按有效狭缝列拟合谱线轨迹 `y(x)`，检查左端、中段、右端都有足够的观测支持。求覆盖区间时取整条曲线的最小和最大行号，包含可能出现在中段的曲线极值。有效照明范围以预览和试扫估计，横向尽量保留完整狭缝及可能进入照明的区间。靠两端缺少可信样本时请求更宽的预览、补拍或用户确认，保留保守的高度。复用 MJSol'Ex 的谱线跟踪与两翼覆盖检查。 [谱线轨迹](https://github.com/Indigo2233/mjsolex-rs/blob/v0.0.3/src/spectrum.rs#L18) · [两翼覆盖](https://github.com/Indigo2233/mjsolex-rs/blob/v0.0.3/src/spectrum.rs#L57)
3. 从中心线到所选各偏移量取全宽包络。上下方向分别保留线型测量所需的拟合与背景范围、重建插值窗口，以及预览中实测的短时漂移余量。只保存线芯时可推荐更窄的高度。开启线宽测量、双翼多普勒或多偏移输出时，重新计算最小高度。相机色散轴的裁切范围随产品配置更新。
4. 将包络转换为相机原始 ROI 坐标，按当前相机和 binning 的偏移及尺寸步进向外对齐。应用前在预览叠加暗线曲线、建议 ROI 和保留边界，显示预计裁切高度。用户可确认、加宽或手动调节。应用后读取硬件实际 ROI，等待新 ROI 的首批图像，再验证左右端、中心弯曲处和谱翼均完整。展示实测预览 FPS，试录时另显示实际写入 FPS。 [相机 ROI 接口](../app/src/main/java/com/indigo/mobileobservatory/camera/Camera.kt#L73)

### 5.2 校验和回退

低信噪比、暗线重复、ROI 读回不一致或谱线接近边界时，提示具体原因并保留上一次通过检查的 ROI 或建议加宽。用户改变谱线、偏移量、binning 或旋转配置后，重新确认包络。自动扫通过试扫确认谱线在进入与离开日面时都落在 ROI 内。元数据记录硬件实际 ROI、选中的谱线、像素偏移和适用的漂移余量。

## 6. 扫掠位置与线视场仿真

### 6.1 共享模型

在现有虚拟支架接口上新增太阳线扫场景。自动扫控制器沿用实机的运动、停稳、录制和终点判定接口。仿真底层用可控时钟分别产生真实位置、延迟后的支架坐标读回和相机采集事件。运动模型可设置太阳跟踪、双向速率、加速、减速、换向回差、指令延迟、坐标读回延迟和断连。16× 实拍用时作为预设起点，仿真参数由独立配置指定及调整。 [虚拟支架接口](../app/src/main/java/com/indigo/mobileobservatory/simulation/VirtualMountSession.kt#L6)

把太阳盘和狭缝放在同一个局部天球平面中。设太阳半径为 `R`，太阳中心到狭缝直线的带符号垂距为 `d(t)`。当 `abs(d) ≤ R` 时，狭缝与理想太阳盘的交线长度为 `2 × sqrt(R² − d²)`。再按狭缝长度和太阳中心沿狭缝的偏移求交，得到各帧实际被照亮的狭缝列。盘外天空及可选日珥信号独立建模。帧内横向是狭缝空间采样，纵向为光谱采样。在照亮的列上渲染可调倾斜、弯曲、线宽和漂移的暗线，从而生成可送入 ROI 推荐、SER 写入和 Rust 重建的合成光谱。曝光期间对位置采样积分，以区分曝光拖影和帧间采样不足。

### 6.2 调试显示与自动断言

- 调试页显示太阳圆盘、狭缝有限线段、瞬时交线、A/B 端点和扫掠轨迹。可按时间逐帧查看相机看到的光谱，同时以颜色区分加速、稳定、减速和停稳区。单独显示真实位置与控制器实际收到的延迟坐标。支持暂停、单步和查看反向一趟。
- 主要验收证据为每趟的文本日志和覆盖报告。报告记录首次入盘、最后离盘、稳定区起止、两端最小留白、速度范围、实际帧率和曝光模糊量。用仿真真实状态断言加减速不与日面重叠、两趟都覆盖整个盘且回扫成图朝向一致、停稳前不换向、异常趟不删除原片。控制器只能读取模拟设备接口，测试断言才使用真实轨迹。
- 至少覆盖双向近 6 秒的正常试扫、起点余量太小导致加速入盘、长回差、停机过冲、慢读回、曝光过长或目标帧率不足、谱线两端逼近 ROI 边界、低空间与中途断连。合成日面加入非对称位置标记来判断回扫方向。实拍 SER 回放用于验证真实信噪比与谱线曲率，合成输入用于验证位置与线视场的对应关系。

## 7. Rust 接入、排队与性能

- 在 MJSol'Ex 将算法核心与独立 Android UI 解耦，通过固定 Git 修订和 Cargo 锁文件集成。靛空台新增薄 JNI 层，在后台线程一次传入文件和设置，包括谱线参考、校准、方向、内存余量、必选产物及暂存目录。返回实际重建设置、产物清单、关键警告及失败原因。取消在已有 Rust 进度回调处检查。
- 对靛空台自有 SER 使用可随机读取的文件，Rust 直接读取。完整帧、重建像素及多个大图保持在 Rust 和文件侧。Kotlin 按需加载预览尺寸，保存列表接收路径和元数据。对于素材库导入的外部文件，沿用靛空台的本地导入与访问流程。
- 第一趟可由用户确认谱线，后续各趟从同一参考重定位。定位置信度不足时保留原片并标记待检查，用户可调整后重建。线芯、双翼偏移、温度或平场需要记录时，沿用可获得的采集元数据。省略缺失的测量量。
- 首版串行执行。每趟录完后在盘外停稳，完成重建和结果提交后再开始下一趟。验证录制和重建并行时的丢帧率、存储写速、内存和温度后，可启用单个重建作业和单个等待位，使下一趟采集与上一趟重建重叠。达到待处理上限或低空间阈值时，在两趟之间暂停。启动前预留一趟 SER、写入暂存和必选输出的空间。按实际 ROI、每像素字节数和实测写入帧率估算 SER 体积。录制时长采用含两端盘外余量的整趟用时。异常耗尽空间时停止采集并保留已写文件。
- 已有实拍样本为 3840 × 40、16 位、3139 帧，约 964 MB。20 趟的 SER 约 19.3 GB，另计产物和暂存。回收站在清理前继续占用容量。以靛空台目标手机的实际采集、重建与导出耗时确定并行策略。
- 复用当前 Gradle 与 NDK 构建路径，覆盖生产 ARM64 和现有模拟测试所需的 ABI。核心遵循 Apache-2.0 及 NOTICE。BASS2000 参考曲线另按 CC BY-NC-SA 4.0 授权。把图集设为独立构建选项，商业构建在取得适用授权前关闭该选项。图集独立于线扫重建。 [许可说明](https://github.com/Indigo2233/mjsolex-rs/blob/v0.0.3/NOTICE)

## 8. 结果提交、重启恢复与七天清理

### 保存与处置顺序

1. 分配稳定的任务 ID 和趟号。在与最终结果同卷的隐藏暂存目录写入用户选定的产物，并关闭文件。打开验证文件格式、尺寸和完整性。检查所选文件均已生成。
2. 写入清单，记录原始文件标识、观测时间、实际方向、曝光、硬件实际 ROI、有效帧区间及其判定依据、写入和丢帧数、重建设置、算法版本、产物路径与警告。将一趟的目录作为整体提交，再更新本地记录。素材库通过已提交的清单显示和分组，即使应用在提交前后退出也可以确定当前状态。
3. 根据已确认的原片策略执行处置。仅处理该自动任务创建且匹配文件标识的 SER，确认文件没有被重建、分享或编辑占用。素材库手动重建保留其输入。处置失败时记录原因，允许再次处置，结果继续保留。

重启时根据已提交目录、任务记录和原片状态恢复。重新执行同一趟使用原趟号，避免重复发布结果、重名覆盖或把用户恢复的原片再次移入回收站。未封口、主动停止或异常掉线的文件单独标记。系统保留可读的部分，供人工检查。已封口的正常文件可重新排队。

### 回收站

- 回收站条目增加 `trashedAtUtc`，用首次成功移入的时间加 7 天得到到期时间。沿用原路径记录和附属文件联动。删除、恢复与自动清理共用同一访问锁。正在使用的条目延后处理。
- 用 Android 后台任务和启动时巡检触发清理。仅删除已满 7 天且带有效到期记录的条目。系统休眠或后台调度延迟时，在下一次允许运行时清理。已有缺少入站时间的条目继续保留，用户可手动管理。
- 在回收站显示到期时间和恢复入口。「直接删除」在结果提交后执行并立即释放相应空间。处置动作只适用于本次记录的原片及其附属文件。
