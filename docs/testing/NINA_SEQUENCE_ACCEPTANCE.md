# NINA sequence compatibility acceptance

本清单用于记录桌面 NINA、Android 真机与手机竖屏之间的序列兼容性证据。每次验收记录以下信息：

- 应用提交、APK SHA-256、签名证书指纹；
- 手机型号、Android 版本、屏幕分辨率、显示大小和字体缩放；
- NINA 版本、序列文件名和原始文件 SHA-256；
- 每个检查项的通过、失败或无法执行状态；
- 脱敏后的原始文件、导出文件、截图和日志位置。

## 自动化基线

执行以下命令：

```powershell
.\gradlew.bat testDebugUnitTest --tests "com.indigo.mobileobservatory.sequence.*"
.\gradlew.bat compileDebugAndroidTestKotlin -PemulatorTest=true -PsequenceEnabled=true
```

`NinaCompatibilityAcceptanceTest` 使用手写夹具
`app/src/test/resources/sequence/nina-retained-nodes.json`，覆盖复杂文件往返、表达式原文、`$id`/`$ref`、五层嵌套、循环计数、深层编辑、链接模板、外部脚本、连接、符号、圆顶、安全监视器、平场向导、开关和子帧 ROI。

`SequencePortraitUsabilityTest` 使用 360×640 dp 竖屏视口，滚动到第六层指令集，打开该层的添加面板，添加消息框，再滚动到结束区。连接 Android 设备后可单独执行：

```powershell
$env:ANDROID_SERIAL = '<device-serial>'
.\gradlew.bat connectedDebugAndroidTest `
  -PemulatorTest=true `
  -PsequenceEnabled=true `
  '-Pandroid.testInstrumentationRunnerArguments.class=com.indigo.mobileobservatory.ui.SequencePortraitUsabilityTest'
```

## 验收文件

在当前 NINA 版本中创建一份文件，至少包含以下结构：

1. 开始区：连接设备、打开圆顶、等待安全、外部脚本、符号定义。
2. 目标区：两个深空目标、智能曝光、两层循环条件、中天翻转触发器、抖动触发器。
3. 任一数值字段使用符号表达式，例如曝光时间 `ExposureSeconds * 2`。
4. 一个链接模板容器。
5. 一个平场向导节点。
6. 一个带明确 `X`、`Y`、`Width`、`Height` 和 binning 的子帧曝光节点。
7. 至少六层嵌套指令集，最深层包含一个普通曝光和一个保留节点。
8. 结束区：关闭圆顶或断开设备。

保留 NINA 生成的原始文件。手机和 NINA 每次保存均使用新文件名，便于逐步比较。

## NINA 到手机再回到 NINA

1. 在 NINA 中打开原始文件，确认全部节点、目标、条件和触发器可见。
2. 将文件复制到真机，通过应用的导入功能打开。
3. 检查预检列表：表达式和保留节点均有明确问题项；普通可执行节点不受这些问题项影响。
4. 展开每类保留节点，核对路径、名称、表达式、ROI 和厂商扩展字段。
5. 修改最深层普通曝光的时间，在同一层添加批注，保存并导出为新文件。
6. 用 NINA 打开手机导出文件，核对三区、两个目标、所有嵌套层级、条件、触发器和普通曝光修改。
7. 核对以下字段保持完整：
   - 所有保留节点的 `$type`；
   - 原始 `$id` 和指向它们的 `$ref`；
   - 表达式对象、`Definition` 和数值快照；
   - 外部脚本路径及参数；
   - 链接模板引用；
   - 平场向导参数；
   - 子帧 ROI 的 `X`、`Y`、`Width`、`Height` 和 binning；
   - 应用未识别的扩展属性和数组。
8. 在 NINA 中另存一次，再次导入手机，重复第 4 项和第 7 项。

通过标准：NINA 两次打开均无反序列化错误；应用修改的已知字段符合预期；上述保留字段逐项一致。

## 手机到 NINA 再回到手机

1. 在手机中新建高级序列，建立开始、目标、结束三区和至少三层嵌套。
   - 导出 JSON 中根节点包含全局 `Triggers`；开始、目标、结束三区只包含 `Items`，不包含区级 `Conditions` 或 `Triggers`。
2. 添加循环条件、智能曝光、中天翻转和抖动触发器，填写目标坐标与位置角。
3. 导出文件，在 NINA 中打开，核对结构、参数、图像类型、滤镜、增益、偏置和 binning。
4. 在 NINA 中添加一个外部脚本、一个链接模板和一个子帧曝光，另存为新文件。
5. 将新文件导回手机，确认新增节点出现，预检问题明确，原有手机节点仍可编辑。
6. 再次导出并用 NINA 打开，确认新增节点及其字段保持完整。

通过标准：两个方向均能连续完成打开、编辑、保存和再次打开；节点顺序、父子关系和参数保持一致。

## 表达式运行行为

1. 打开含 `ExposureSeconds * 2` 的文件，确认预检将对应节点标为含表达式。
2. 启动序列，确认运行到该节点时暂停，当前节点定位准确，提示包含表达式暂不支持的信息。
3. 点击跳过当前，确认后续普通曝光继续执行。
4. 保存并导出，确认表达式 `Definition`、表达式对象和数值快照保持完整。

通过标准：预检与运行时指向同一节点；跳过只影响当前节点；后续节点完成；表达式原文完整。

## 保留节点运行行为

按下表逐项执行。每项均在其后放置一个一秒普通曝光。

| 类别 | 代表节点 | 检查 |
|---|---|---|
| 圆顶 | `OpenDomeShutter` | 暂停、节点名准确、跳过后曝光执行 |
| 安全监视器 | `WaitUntilSafe` | 暂停、跳过后曝光执行 |
| 连接 | `ConnectEquipment` | 暂停、选择项字段保留 |
| 符号 | `Constant`、`Variable` | 暂停、名称和值保留 |
| 外部脚本 | `ExternalScript` | 暂停、路径和参数保留 |
| 链接模板 | `LinkedTemplateContainer` | 整个容器保留、跳过后同级节点执行 |
| 平场向导 | `AutoExposureFlat` | 暂停、直方图参数保留 |
| 子帧 ROI | `TakeSubframeExposure` | 暂停、ROI 与 binning 保留 |

通过标准：每个节点均可识别、保存和导出；运行时暂停；跳过后同级后续节点继续。

## 手机竖屏深层嵌套

分别使用 360 dp 和 412 dp 宽度执行，系统导航模式至少覆盖手势导航。字体缩放使用 100% 和 200%。

1. 打开六层嵌套文件，保持全部层级展开。
2. 点击全部折叠，确认嵌套内容隐藏且结束区可快速到达；点击全部展开，确认六层结构恢复。
3. 从顶部滚动到第六层，记录完整屏幕滑动次数。
4. 展开最深层普通曝光，依次编辑曝光、增益和 binning。软键盘显示时保存、折叠和添加入口保持可触达。
5. 在第六层点击添加指令，确认底部面板完整展开，搜索框、显示暂不可执行指令和结果列表可见。
6. 搜索并添加消息框，确认插入到第六层，面板关闭后仍停留在相邻位置。
7. 折叠第三层，确认其后代隐藏；再次展开并滚动到第六层。
8. 滚动到结束区并添加一条批注。
9. 启动序列，运行到深层节点时检查当前节点定位；手动滚动后检查返回当前节点入口。
10. 保存、退出页面、重新打开，确认展开状态、节点顺序和编辑结果。

通过标准：全部操作无需旋转屏幕；控件无重叠或截断；软键盘不会遮挡提交操作；添加面板无需二次拖动即可使用；最深层和结束区均可通过滚动到达。记录滑动次数，作为后续压缩树形布局的比较基线。
