# 器材界面与设置界面优化计划

## 实施状态

- 阶段 1 已实施：器材页提供连接、相机、赤道仪、滤镜轮、电调焦、平场板/镜头盖和 CAA 二级 Tab。
- 阶段 2 已实施：附件控制区已拆分至对应器材子页面；相机和赤道仪子页面提供状态摘要与原控制页入口。
- 阶段 3 已实施首期：新增按相机、电调焦、平场板设备名称或序列号分区的设置仓库；滤镜轮继续使用现有槽位配置存储。
- 阶段 4 已实施首期：QHY、ToupTek、ZWO 和 Player One 相机已接入 Offset/Black Level 能力探测、范围读取、默认值保存与写入；QHY 已接入 SDK 原生读出模式列表。平场板角度预设已可保存。Gemini、DLC/Oasis 平场板协议尚未提供绝对角度控制，控制页继续使用打开、关闭和停止指令。
- 阶段 5 待执行：需要在真实设备上完成 Oasis 一代/二代、Gemini、各滤镜轮和各相机 SDK 的回归验证。

## 1. 背景

当前器材扫描、连接、识别和控制集中在 `AccessoriesScreen`，电调焦、平场板、CAA、滤镜轮共用同一纵向页面。相机与赤道仪的连接和控制分布在各自主页面，器材配置同时分散在界面状态、`SharedPreferences` 和部分设备控制器中。

本计划建立统一的器材连接入口、独立的器材控制子页面和按器材分类的设置体系。页面根据设备能力动态显示功能，并保持现有相机、赤道仪和附件控制器的兼容性。

## 2. 目标

1. 器材页为每类器材提供独立二级 Tab。
2. 扫描、识别、授权、连接和断开集中到连接子页面。
3. 每类器材拥有独立控制子页面，只展示运行状态和日常操作。
4. 设置页按器材分类，保存设备级配置和默认参数。
5. 平场板支持开合角度配置；协议缺少角度能力时自动隐藏相关项目。
6. 相机设置覆盖读出模式、增益、Offset、像素格式和制冷默认值。
7. 滤镜轮设置覆盖槽位数量、各孔位名称、双向模式和校准。
8. 电调焦设置覆盖微调步数、粗调步数、方向、最大行程和回差补偿。
9. 配置按设备身份隔离，同类设备切换后可恢复对应参数。

## 3. 设计原则

- 连接流程与运行控制分离，连接状态由统一入口管理。
- 通用 UI 只依赖器材能力接口，厂商协议保留在现有适配器内。
- 控制页面显示当前设备实际状态，设置页面管理默认值和持久参数。
- 不支持的功能依据能力探测结果隐藏，并在设置项旁显示来源和适用设备。
- 首期通过 Repository 封装现有 `SharedPreferences`，后续可平滑迁移至 DataStore。
- 保持相机、赤道仪和附件连接相互独立，单个设备故障不影响其他器材。

## 4. 信息架构

### 4.1 一级页面

保留当前主要功能入口：

```text
相机 | 赤道仪 | 星图 | 器材 | 设置
```

相机和赤道仪一级页面继续承担成像、导星、指向等高频业务。器材页集中管理所有硬件连接，并提供附件和设备级快捷控制。

### 4.2 器材页二级 Tab

```text
器材
├─ 连接
├─ 相机
├─ 赤道仪
├─ 滤镜轮
├─ 电调焦
├─ 平场板/镜头盖
└─ CAA
```

- 使用 `ScrollableTabRow` 适配手机窄屏。
- 记住最近选择的二级 Tab。
- 已连接设备在 Tab 标题旁显示状态标记。
- 设备正在移动、曝光或校准时显示忙碌状态。
- 未连接页面显示设备说明、当前状态和跳转至连接页按钮。
- 平板和横屏阶段可将二级 Tab 替换为左侧导航栏，页面路由和状态模型保持一致。

### 4.3 连接子页面

连接页统一显示：

1. 已发现设备列表及器材类型。
2. USB 权限、串口探测、蓝牙和网络连接状态。
3. 自动识别结果、厂商、型号、序列号和固件版本。
4. 连接、断开、重新扫描和手动指定器材类型操作。
5. 设备占用、连接超时、协议不匹配和权限错误。
6. 每个已连接设备的“进入控制”入口。
7. 相机、赤道仪和附件的独立连接状态，避免一个连接任务阻塞其他设备。

连接页沿用现有控制器和连接方法，首期只重组 UI 与状态，不改动协议实现。

## 5. 各器材控制子页面

### 5.1 相机

- 连接状态、型号、传感器温度和制冷功率。
- 曝光、增益、Offset、读出模式和像素格式的当前值。
- 开始/停止预览和曝光的快捷入口。
- 跳转至完整相机成像页面。
- 参数范围由当前相机能力提供。

### 5.2 赤道仪

- 连接状态、赤经赤纬、跟踪状态和移动状态。
- 停止、跟踪开关和常用移动速率。
- 跳转至完整赤道仪控制页面。

### 5.3 滤镜轮

- 当前槽位、槽位名称、移动状态和设备信息。
- 按名称选择滤镜。
- 停止和重新读取位置。
- 校准操作按设备能力显示。
- 槽位编辑迁移至设置页，控制页保留设置入口。

### 5.4 电调焦

- 当前位置、温度、移动状态和最大行程。
- 向内/向外微调和粗调。
- 绝对位置移动、停止、位置归零。
- 按设备能力显示速度、方向和温度信息。
- 控制按钮读取当前设备对应的微调、粗调配置，移动步数必须大于零。

### 5.5 平场板/镜头盖

- 当前开合状态、目标角度、运动状态和光源状态。
- 打开、关闭、停止。
- 支持角度时提供目标角度滑块和数值输入。
- 亮度调节、光源关闭和默认亮度恢复。
- 控制页中的打开、关闭操作分别使用设置中的全开角度和全关角度。

### 5.6 CAA

- 当前角度、步数、运动状态和每度步数。
- 绝对角度、相对角度和停止。
- 零位、方向、保持力矩等操作按设备能力显示。

## 6. 设置页结构

设置页采用分类列表或二级 Tab：

```text
设置
├─ 通用
├─ 相机
├─ 赤道仪
├─ 滤镜轮
├─ 电调焦
├─ 平场板/镜头盖
├─ CAA
└─ 诊断与关于
```

每个器材设置页顶部提供设备选择器。当前已连接设备优先显示，同时允许编辑历史设备配置。设置项标记以下状态：

- 本地默认值。
- 当前设备值。
- 可写入设备。
- 下次连接时应用。
- 当前设备不支持。

## 8. 能力模型

### 8.1 通用能力

为设置和控制页面提供只读能力描述：

```kotlin
data class DeviceCapability<T>(
    val supported: Boolean,
    val writable: Boolean,
    val range: ClosedFloatingPointRange<T>? = null,
    val step: T? = null
)
```

界面通过能力描述决定设置项的可见性、范围、步长和写入方式。

### 8.2 平场板角度能力

在 `CoverCalibratorController` 增加可选角度能力：

```kotlin
val supportsCoverAngle: StateFlow<Boolean>
val coverAngle: StateFlow<Double?>
val coverTargetAngle: StateFlow<Double?>
val coverAngleRange: StateFlow<ClosedFloatingPointRange<Double>?>

fun moveCoverToAngle(angle: Double)
```

实施前调研 Gemini、DLC/Oasis 及后续设备协议：

1. 确认协议是否提供绝对角度、相对角度或位置百分比。
2. 确认角度范围、方向、精度和状态查询指令。
3. 确认运动中停止和断电位置保存行为。
4. 仅提供开关指令的设备继续使用打开、关闭、停止三态控制。

### 8.3 相机 Offset 与扩展参数

建立通用数值参数接口，统一 QHY、Player One、ToupTek 等厂商参数：

```kotlin
enum class CameraControlId {
    GAIN,
    OFFSET,
    USB_BANDWIDTH,
    GAMMA
}

data class CameraNumericControl(
    val id: CameraControlId,
    val range: ClosedFloatingPointRange<Float>,
    val step: Float,
    val current: Float,
    val writable: Boolean
)
```

各相机适配器将厂商 SDK 参数映射到通用控制项。设置页面只展示当前设备返回的控制项。

当前 Offset 能力确认与实现状态：

| 厂商 | SDK 参数 | 实现状态 |
| --- | --- | --- |
| QHY | `CONTROL_OFFSET` | 已实现能力探测、范围/步长/当前值读取和写入 |
| ToupTek/图谱 | `TOUPCAM_OPTION_BLACKLEVEL`，能力位 `TOUPCAM_FLAG_BLACKLEVEL` | 已实现按当前位深计算范围、读取和写入，界面显示为 Black Level |
| ZWO | `ASI_BRIGHTNESS` | 已实现控制能力、可写性、范围和当前值读取及写入 |
| Player One/头号玩家 | `PoaConfig.OFFSET` | 已实现属性范围、可读写性、当前值和预设联动 |
| 大恒工业相机 | GenICam `BlackLevel` | 当前工程尚无大恒 SDK、品牌枚举和相机适配器，待大恒相机接入时映射到 `CameraOffsetCapable` |

## 9. 配置与持久化

### 9.1 Repository

新增统一配置仓库：

```text
DeviceSettingsRepository
├─ CameraSettings
├─ MountSettings
├─ FilterWheelSettings
├─ FocuserSettings
├─ CoverSettings
└─ RotatorSettings
```

首期继续使用现有 `SharedPreferences` 存储，通过 Repository 统一键名、默认值、迁移和数据校验。页面和 ViewModel 停止直接拼接配置键。

### 9.2 设备身份

优先使用稳定身份生成配置作用域：

1. 相机：厂商、型号、序列号。
2. USB HID：VID、PID、设备序列号。
3. USB 串口：VID、PID、USB 序列号；缺少序列号时使用设备路径作为临时标识。
4. 网络设备：协议类型、主机、端口和设备名称。

设备路径变化导致临时身份失效时，设置页提供复制配置功能。

### 9.3 配置应用流程

```text
连接成功
  → 读取设备身份
  → 读取设备能力与当前值
  → 加载对应本地配置
  → 校验范围和兼容性
  → 应用允许自动写入的配置
  → 更新控制页状态
```

危险操作和耗时操作需要用户明确触发，包括校准、固件写入、大范围位置移动和覆盖设备内参数。

## 11. 分阶段实施

### 阶段 1：导航骨架与统一连接页

1. 新增器材二级 Tab 和页面路由状态。
2. 将 `AccessoriesScreen` 的扫描、识别和连接区域迁移至 `DeviceConnectionPage`。
3. 增加已连接设备摘要和进入控制入口。
4. 保持现有连接方法与控制器调用不变。
5. 补充页面状态恢复和空状态。

交付结果：所有现有设备可从统一连接页完成连接和断开。

### 阶段 2：分离器材控制页

1. 迁移滤镜轮、电调焦、平场板和 CAA 控制组件。
2. 增加相机和赤道仪设备摘要页。
3. 增加未连接、忙碌、错误和能力受限状态。
4. 统一停止按钮、数值输入校验和操作反馈。
5. 删除旧器材页中的重复控制区域。

交付结果：每类器材拥有独立控制子页面，连接与控制状态互不阻塞。

### 阶段 3：配置 Repository 与分器材设置页

1. 建立配置数据类、设备身份和 `DeviceSettingsRepository`。
2. 迁移现有 SharedPreferences 键并保留兼容读取。
3. 新增设置分类导航和设备选择器。
4. 迁移滤镜轮槽位编辑。
5. 接入电调焦步数、方向、最大行程和回差设置。
6. 接入相机读出模式、增益、像素格式和制冷设置。

交付结果：配置按设备保存，并可从独立设置页管理。

### 阶段 4：平场板角度与相机 Offset

1. 调研平场板协议角度能力。
2. 扩展 `CoverCalibratorController` 可选能力。
3. 实现角度控制、校准和范围校验。
4. 建立相机通用数值参数能力。
5. 为各厂商适配器映射 Offset 和其他扩展参数。
6. 对缺少能力的设备隐藏对应设置。

交付结果：支持角度的平场板可配置并移动至指定角度，支持 Offset 的相机可保存和应用默认值。

### 阶段 5：迁移、响应式布局与回归

2. 优化横屏和平板导航。
3. 补充连接超时、重连和错误提示。

交付结果：新界面覆盖现有设备能力，历史设置可继续使用。

## 13. 验收标准

1. 用户可在器材页完成所有已支持器材的扫描、连接和断开。
2. 相机、赤道仪、滤镜轮、电调焦、平场板和 CAA 均有独立控制子页面。
3. 一个器材的连接失败不会改变其他器材的连接和控制状态。
4. 滤镜轮每个孔位可设置名称，控制页按名称显示。
5. 电调焦微调和粗调按钮使用非零配置步数，回差设置可按设备能力写入。
6. 支持角度的平场板可配置全开、全关和默认工作角度，并可停止运动。
7. 相机可保存支持范围内的读出模式、增益和 Offset。
8. 同类多设备配置相互隔离，重新连接后恢复对应设置。
9. 历史设置迁移后继续生效。
10. 日志导出、日志清理和关于信息继续可用。

## 14. 风险与兼容策略

| 风险 | 处理方式 |
| --- | --- |
| 厂商协议缺少平场板角度指令 | 保留打开、关闭、停止操作，隐藏角度设置 |
| 相机 SDK 参数范围和单位不同 | 在厂商适配器内完成映射和范围换算 |
| 设备缺少稳定序列号 | 使用临时身份并提供配置复制 |
| 自动应用参数引发意外动作 | 默认只自动应用安全参数，运动和校准需要用户触发 |
| ViewModel 一次性拆分影响范围大 | 使用代理接口分阶段迁移 |
| 二级 Tab 在手机上过密 | 使用可横向滚动 Tab，并保留清晰状态标记 |
| 设备配置与设备内参数冲突 | 明确显示本地值、设备值和写入方向 |

## 15. 推荐实施顺序

优先完成阶段 1 至阶段 3，形成稳定的页面结构和配置基础。平场板角度与相机 Offset 依赖协议和 SDK 能力调研，安排在阶段 4。每个阶段保持可构建、可运行，并对现有 Oasis、Gemini、电调焦和滤镜轮连接流程执行回归。
