## 1. 目标与参考流程

目标是让用户从星图选目标后，按手头器材完成手动推镜、普通 GOTO 或光学校验后的指向并居中。安装方式和设备能力可不同，但目标、校准状态、误差与返回来源共享。连接手机、相机、架台和配件始终互相独立。

Celestron StarSense Explorer 的可借鉴流程是：先建立手机与望远镜之间的对应关系，再选目标，按箭头移动，停稳后依据星野定位确认目标进入视场。它不等同于只有罗盘箭头，也不等同于面向电动架台的 StarSense AutoAlign。参考 [官方技术说明](https://www.celestron.com/pages/starsense-explorer-technology) 和 [官方应用快速指南](https://celestron-site-support-files.s3.us-east-1.amazonaws.com/support_files/StarSense_Explorer_App_QSG_5%20languages_2021.pdf)。以下多相机、架台回写和任意固定安装关系是本项目的设计推导，不宣称是 SSE 的内部实现。

## 3. 先识别能力，再推荐路径

设备是否连接、能否执行命令、坐标是否可信是三件事。协议能力留在 adapter；物理安装关系由用户确认；软件不能从“USB 主相机”或型号名推断它装在哪条光路上。

| 维度 | 需要知道什么 | 能决定什么 |
|---|---|---|
| 主镜终端 | 目镜，或实际可拍摄并可解算的相机；参考中心对应全幅、ROI 还是指定光轴像素 | 用亮星居中作参考，或直接取得主镜光学参考 |
| 手机 | 物理镜头身份、拍摄/星野解算能力、传感器可用性 | 绝对星野定位、短时相对姿态、只有粗略朝向，或无法作为指向源 |
| 支架 | 固定；可调且能锁紧；使用中会相对镜筒移动；相机是否持续看见天空 | 能否复用标定。刚性固定即可，允许非同轴 |
| 辅助光路 | 相机装在主镜、导星/寻星镜还是其他设备；是否有到主镜的有效关系 | 辅助解算能否代表主镜，而不是只代表自己 |
| 架台协议 | 连接、坐标读取、GOTO、SYNC、跟踪、手动控制分别支持与否 | 分别启用对应操作；不能用一个 `connected` 或 `canControl` 代替 |
| 轴读数 | 电机步数/位置计数器/辅助编码器；时间戳、分辨率、零位和模型版本；松离合后是否仍可观测运动 | 能否提供相对运动辅助，不能直接证明天球绝对精度 |
| 几何和环境 | 赤道/地平模式、地点时间、当前光路与安装版本、机械活动范围 | 换算、引导方向、有效性及自动采样范围 |

AZ-EQ6 官方手册描述的是可辅助记录手动转动的辅助编码器，不能据型号名认定为高精度绝对天球坐标源；能否读到、是否启用、精度和坐标连续性必须在当前连接协议下核实。当前电机适配器查询轴位置，SYNC 还会改写控制器位置计数，不能直接当作独立编码器数据。参考 [AZ-EQ6 官方手册 §5.1](https://inter-static.skywatcher.com/upfiles/en_download_caty01353096919.pdf)、[SkyWatcherMotorAdapter](../app/src/main/java/com/indigo/mobileobservatory/mount/SkyWatcherMotorAdapter.kt)。

### 能力组合与建议路径

| 当前组合 | 推荐校准/准备 | 能提供的引导 |
|---|---|---|
| 仅手持手机或支架不能锁紧 | 可浏览星图、解析手机画面；不保存固定镜筒关系 | 手机朝向辅助；不能确认目标已进镜筒 |
| 目镜 + 固定手机，无架台连接 | 亮星居中与手机解算配对，再换星验证 | 经标定的镜筒手动推镜 |
| 主镜相机 + 固定手机，无架台连接 | 两路解算配对；手动换方向验证 | 自动求安装关系、手动推镜、主镜验证 |
| 导星/寻星相机 + 目镜 | 先建立该相机到主镜的关系 | 辅助光路作为参考；手机可选 |
| 上述任一路径 + 只读架台 | 保留独立光学标定，再比较架台回读 | 回读可视化与诊断；相对辅助取决于轴观测能力 |
| 可 GOTO 但不支持 SYNC | 自动移动采样或 GOTO 后板解纠偏 | 普通 GOTO / 适用的纠偏居中，不显示可写同步 |
| 支持 SYNC | 明确参考来源、时刻与目标光路后写回 | 更新架台模型；需另一次独立观测检验 |
| 仅架台，无可验证光学源 | 沿用架台自身已完成的初始化/对齐 | 架台估计指向和普通 GOTO，不显示“已光学验证” |

有相机不保证能解算；有 SYNC 不保证架台已完成必要初始化；有编码器不保证松离合后的变化可读。条件不成立时给一个恢复动作，并保留其他可用路径。

## 4. 坐标、观测与存储契约

“手机里存储的坐标”不是第四个物理坐标系，而是带来源的观测、关系和估计。以下概念必须分开：

| 对象 | 含义 | 禁止混用 |
|---|---|---|
| 手机相机天球姿态 | 相机中心方向、图像滚转、像素射线与天球的对应 | 未标定时不能标成镜筒轴 |
| 镜筒天球方向 | 当前工作光路的光轴方向；可能由主镜直接测得或由已标定源推算 | 与取景框屏幕中心、任一相机 ROI 中心混淆 |
| 架台回读 | 控制器按其零位/对齐模型算出的天球坐标 | 与独立板解真值混淆 |
| 目标坐标 | 用户想去的位置，带历元和对象身份 | 与当前测得位置或已到位混淆 |
| 标定关系 | 内参、相机/机身关系、手机到镜筒轴、辅助光路到主镜、架台模型修正 | 把所有关系压成一个 RA/Dec 常量偏移 |
| 当前估计 | 某时刻根据上述观测和关系推算出的方向、质量和来源链 | 覆盖原始观测、丢失误差或来源年龄 |

规划的数据契约（尚未实现）：

- **原始观测**：观测 ID、设备/物理镜头/光路 ID、坐标系、单位、曝光中点 UTC 与相应单调时钟时间、地点、实际内参/裁切、姿态/中心、奇偶性、质量和误差。主镜参考必须能说明轴落在哪个像素，ROI 偏移不能变成镜筒偏移。
- **标定关系**：关系 ID 与版本、两端坐标系、模型类型（轴向量或完整姿态变换）、安装/镜头配置指纹、输入观测 ID、拟合及独立验证残差、适用范围、有效/待验证/失效状态与原因。
- **当前估计**：针对哪条光路、估计时刻、最近绝对观测时刻、所用关系版本、光学/IMU/轴读数来源链、估计不确定度及允许的用途。短时传播不能刷新绝对观测的年龄。
- **架台能力及模型**：逐项命令能力、轴读数语义、模型/零位版本；SYNC、重设零位或模式切换要能终止旧版本的相对增量计算。
- **任务**：所选目标、工作光路、执行模式、该次移动/验证序号；过期异步结果不能确认一个更新后的任务。

原始观测不可被“融合结果”回写。向架台 SYNC 后读回相同坐标，仍依赖同一原始观测，不能用来证明该观测或安装标定准确。多个相关来源不能当成独立样本平均以虚增精度。

板解/目录使用 J2000/ICRF；统一架台 API 与星图现有交互使用 JNOW，适配器负责实际线协议差异（例如手控器路径），边界明确转换。Alt/Az 必须附时刻、地点与折射约定；RA 小时与度不能混用。姿态传播使用单调时钟，建立其与曝光时间的可靠映射。

来源选择按当前任务需要的光路、关系有效性、质量、时效和成本决定，不固定“主相机 > 导星 > 手机”。来源冲突要显示并复核，不能默默换源或取平均。主相机被录像/导星等占用时由现有采集所有权协调，不私自抢占；可提示等待或选择可用参考源。

## 5. 手机与镜筒之间究竟标定什么

设 `R_WC(t)` 把经过内参、方向和镜面奇偶性处理后的相机右手坐标系变到同一时刻的天球参考系；`d_W(t)` 是独立测得的镜筒单位指向。

```text
手机坐标中的镜筒轴： b_C = transpose(R_WC(t0)) × d_W(t0)
之后的镜筒方向：     d_W(t) = R_WC(t) × b_C
```

这条轴向量只有两个自由度；已知完整手机姿态和一个可信镜筒方向的配对观测，就可以得到初始解。换方向的独立观测用于验证误差、估计刚性和发现挠曲，不应为凑步骤强制声称必须三颗星才有解。

镜筒轴本身不能约束绕轴滚转。需要相机矩形视场角或完整相机间外参时，另需主相机完整 WCS/相应姿态约束。仅两组 RA/Dec，没有手机图像滚转，不足以建立任意安装角下可跨全天使用的完整变换；单向量最短旋转也不能替代它。

刚性非同轴安装可用，手机和主相机不必看到同一片星场，但必须取得可配准到共同天球参考系、时间一致的观测。支架可调时先锁紧再标定；使用中移动手机会改变关系。安装应在实际推镜范围内持续看见天空，避开镜筒遮挡和地面。

镜面反射会改变奇偶性，不能由普通旋转/四元数自动吸收；每条射线链需要显式镜面或奇偶性处理。白天远目标可以粗调安装和视线，但有限距离视差、无法直接取得天球姿态等限制必须由夜间独立验证补齐。

## 6. 校准引导

### 6.1 共用外壳

从星图的准备状态或开始引导时进入，保留目标与返回来源。只询问尚未知的三类信息：正在用哪条光路、主镜是目镜还是相机、手机是否固定。已有设备与镜头信息自动填入，架台连接始终可选。

主页面只给推荐路径和下一步。替代路径收在“其他方式”；坐标/采样表/矩阵收在诊断，不让新手先选算法或理解外参。动作名称区分“校准手机与镜筒”“验证指向”“同步赤道仪”“移动到目标”。

### 6.2 目镜 + 亮星

1. 从当时可见的亮星中选一颗，引导用户在目镜中心确认；低倍寻找、需要时用十字丝目镜精确居中。
2. 手机保持固定，镜筒停稳，拍星野取得完整相机姿态。记录用户居中确认与曝光时间；若镜筒/天体在期间移动，应补偿或重采。
3. 形成初始轴关系后换一颗位置有区别的亮星，独立检查是否在目镜中心；保存真实残差/用户确认精度与配置。

可选“白天粗调”只帮助安装，不以固定演示数字显示高精度完成。手机不能拍出可解星野时给出拍摄诊断或其他参考路径，不让磁罗盘结果冒充校准完成。

### 6.3 主镜相机 + 手机双解算

1. 确认相机确实位于主镜、光轴参考像素/ROI 关系和两路实际镜头身份。
2. 在镜筒稳定时配对拍摄与解算。两路曝光中点统一时刻，处理跟踪/地球自转；无法保证配对误差时拒绝该样本。
3. 求初始轴关系，手动换方向做独立验证。支持 GOTO 时可由用户选择“自动移动验证”，明确采样范围并始终可 STOP；不强制 GOTO 才能标定。

主镜只有中心解算时只能给轴参考；需要完整旋转关系时要求有效 WCS、像面方向和奇偶性。保存记录包含匹配质量与独立验证，失败不覆盖旧的有效标定。

### 6.4 辅助光路与架台

寻星/导星相机必须先通过亮星居中或主镜配对建立“辅助相机 → 主镜”关系。只有辅助相机本身解算成功，不能直接宣称主镜到位。

架台可参与自动换点和相对运动辅助。比较独立光学结果与架台回读后，若支持 SYNC，可单独同步；一次 SYNC 通常是局部模型修正，不等于极轴校准、多星全局指向模型或免除所有手控器初始化。若需免手动多星的自动对齐，须按各协议模型单独设计和验证。

现有“指向并居中”任务的名称和执行说明须明确：支持 SYNC 的适配器可能写回坐标；仅“验证指向”不写回。自动流程在开始时说明运动与写回行为，不在每个已授权采样点再堆确认框。最终以独立光学观测验收，不能以刚刚写入的回读值验收。

## 7. 标定有效性与局部失效

| 变化 | 保留什么 | 重新计算/验证什么 |
|---|---|---|
| 整个镜筒连手机一起移动 | 手机到镜筒的刚性关系 | 当前姿态、传播误差；停稳后按验证状态拍摄 |
| 手机松动、移位、拆装或支架重新调节 | 主镜相机等其他独立关系 | 手机安装关系失效，重新标定 |
| 切换物理镜头 | 原镜头配置的历史标定 | 使用已验证的新镜头关系，否则重校；不能全用 sourceId=phone |
| 分辨率、数字裁切、ROI 改变 | 机械关系可保留 | 更新内参/像素到光轴变换；元数据不足时暂不能确认 |
| 屏幕横竖屏变化 | 机械关系和观测数据 | 只更新 UI/显示坐标映射，不应要求重新安装标定 |
| 只换目镜焦距且光轴未变 | 轴关系 | 更新视场、容差和必要的居中检查 |
| 换天顶镜、改变相机安装、引入/转动镜面 | 不受影响的其他光路 | 受影响的轴、滚转、奇偶性关系重新验证 |
| 只转相机角度 | 理想轴线可能不变 | 更新滚转；实际偏心/ROI 中心变化需检查轴关系 |
| 绝对定位变旧、传感器漂移、遮挡 | 安装标定可仍有效 | 当前估计降级，重新定位；不能自动删除机械标定 |
| 改地点/时间、EQ/AZ 模式、零位、架台模型或连接会话 | 与架台无关的机械关系 | 相关天球换算与轴模型有效性重新判断，隔离旧增量 |
| SYNC 或写轴计数 | 独立光学观测与安装关系 | 增加模型版本，禁止跨版本差分，另做独立验证 |

失效提示只指出受影响的关系和一个修复入口，例如“手机位置变了，重新校准”；不让用户从头重填所有器材。配置可持久化，最近“已到位”状态不能跨启动或未知运动直接恢复。

## 8. 引导与到位确认

推荐状态：未准备 → 待校准/待定位 → 可引导 → 移动 → 停稳 → 验证中 → 已验证到位；另有暂用估计、失败/需重试。用户看到短状态和下一步，不看到内部状态枚举。

- 移动时用经过标定的姿态短时传播，手机基线不进行持续星野拍摄；显示预测方向及可信度。
- 慢推、天顶附近与小幅修正都必须让上一轮到位确认过期；不能仅依靠高于 1.2°/s 或累计超过 0.8° 的门限判断“动过”。
- 每次停稳且需要验证时调度新观测；冷却期内停手应在到期后唤醒重试，不能等待另一个可能不会发生的传感器事件。
- 到位由本次移动后、新鲜且合格的独立光学参考确认；IMU 接近目标、旧 `plateSolved` 或架台回读都不能跳过这一步。
- 移动中的曝光、低质量/歧义解算、任务已变或超龄结果不得提交到位。失败后显示暂用估计/重试，有退避与次数/时间上限。
- 角距使用单位向量球面夹角等正确几何，不使用 `hypot(dAlt, dAz)` 作为全天误差。方向提示处理方位环绕、天顶退化和 EQ/AZ 实际可移动方向；到位带滞回。
- 到位阈值结合有效视场、任务要求与总误差预算。目镜圆和相机矩形分别检查容纳范围，不能用同一固定角度声称所有配置都能入框。
- 总误差至少包括解算、安装关系、人工居中/参考像素、时间配对、传播漂移与机械挠曲；误差未知时不展示虚假的精确数字或绿色认证。
- 静止 Dob 固定的是地平指向，RA/Dec 随时间改变，目标会随周日运动离开视场。可减少拍摄，但仍更新坐标、距离与到位有效期，不能一直保留“已到位”。

## 9. 实施顺序与旧里程碑对照

先修统一导航，再建立坐标/能力契约和无架台也能完成的真实校准。电动架台能提高采样效率，但其回读不是独立精度真值，也不是手动 Dob 路径的开发前提。

|---|---|---|
| M0 可行性 | 诊断采集已有；夜间设备矩阵与实拍 go/no-go 未完成 | WF-10、解算计划 P6 |
| M1 手机采集 | 专用 Camera2 采集基础已有，不要求强行占用主成像相机槽 | 元数据/并发所有权验收，WF-05/10 |

## 10. 实拍、精度与能耗验收

手机宽场定位继续采用 [P6 实拍计划](PHONE_WIDE_FIELD_SOLVER_IMPLEMENTATION.md) 与[数据集规范](phone-solve-dataset/README.md)。真实样本和性能基线现在就可采集，不以完成持久化索引为前提。

| 验证对象 | 独立参考 | 记录 |
|---|---|---|
| 手机画面姿态 | 独立参考 WCS，覆盖方向、镜头、裁切、奇偶性 | 成功/拒绝/误解率、中心/旋转/尺度误差、P50/P95 耗时 |
| 镜筒标定 | 未参与拟合的亮星居中或主镜参考 WCS | 样本分布、验证残差、随高度/安装变化的误差 |
| IMU/轴读数传播 | 移动后重新取得的独立光学观测 | 短时漂移、慢推漏检、延迟、模型切换连续性 |
| 手动推镜 | 实际目镜入框/居中与可用主镜参考 | 首次入框率、过冲、耗时、错误到位次数 |
| GOTO/SYNC | 写回后另一次光学观测 | 收敛、误差、支持/不支持 SYNC 路径、STOP、协议初始化要求 |
| 功耗/并发 | 固定设备与操作脚本 | 相机/传感器活跃时间、解算次数、温度、功耗、主相机与导星受影响情况 |

至少 30 组实拍覆盖多镜头、城市/郊区、有月/无月及曝光受限手机；验收样本中不得接受错误解，允许明确诊断的失败。真实镜筒测试还需覆盖固定非同轴、可调后锁紧、移位失效、镜面、不同光路与只读架台。

省电采用事件驱动：移动时不拍星野、停稳后按需验证、空闲降低传感器频率并在适当时机关闭手机 Camera2 session；保留时长/阈值依据实测调参，不沿用未经测量的固定功耗承诺。已到位状态仍受时间和误差约束，不能为了少拍照保留错误认证。

2026-10-14 已接入手机 IMU 的空闲采样策略：连续静止 5 秒后请求 100 ms 周期，移动/停稳过程、明确请求验证以及整个采样解算任务期间请求 20 ms 周期。低频监听持续保留，高频监听按需增减，切换不重置外参、光学锚点、时间线或 IMU 会话；不同队列的过渡旧样本被忽略，同队列时钟倒退及实际超过 500 ms 的采样间断仍使会话失效。100 ms 低频周期留在既有 250 ms 时间线边界内，慢推仍沿用累计运动检测。新增 8 项纯策略/时间线/姿态连续性回归已随全量 JVM 通过，实际送达频率、功耗及温度改善仍待固定设备脚本测量。

沿用“30 分钟找 10 个目标 + 20 分钟静止观测”的可复现脚本，随后做 3 小时真实会话，覆盖 LCD/AMOLED 和低性能机。记录设备、亮度、温度、充电状态、电池计量可用性和基线；电量计不可用时不能报告假精确 mAh。目标是支持整晚合理使用，3 小时无外接电源作为待测目标而非现有承诺。

息屏语音、传感器低功耗唤醒与热状态降级列为后续实验，先确认 Android 生命周期和相机限制、语音可达性及慢推检测，不承诺当前支持后台/息屏持续引导。降级时保留手动验证入口并明确可信度，不能默认改成罗盘“精确到位”。

交互遵循 [全应用规范](INTERACTION_GUIDELINES.md)，验收使用 [统一设计 UX-01–UX-13](OBSERVING_WORKFLOW_DESIGN.md)；算法、真机能力与新手操作分别记录证据，任一项未完成都不能把整套系统记为已完成。
