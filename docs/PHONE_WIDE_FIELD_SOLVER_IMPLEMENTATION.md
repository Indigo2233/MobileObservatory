# 手机内置镜头宽视场解算实施计划

状态（2026-10-13，`7485d04`）：基础路由、元数据、运行时分桶索引、盲解/歧义拒绝和姿态时间线已有；持久化索引、完整姿态传播与实拍验收仍待完成。本轮只核对并更新文档，没有运行新的算法或真机验证。

本文件只负责手机画面解算。镜筒轴换算、标定有效性与架台能力遵循 [指向方案](PHONE_PLATE_SOLVE_PLAN.md)；入口/返回遵循 [统一观测设计](OBSERVING_WORKFLOW_DESIGN.md)；跨模块待办在 [TODO](../TODO.md) WF-05–10。手机画面成功定位不能直接升级为“镜筒到位”。

## 1. 范围与路由

首版目标是手机内置后置物理镜头的离线宽视场亮星解算（WF）。14、24、35、50 mm 等效镜头使用同一套 WF 引擎；视场由本次 Camera2 拍摄实际焦距、有效传感器区域、裁切和输出尺寸计算。

统一路由的设计与 `PlateSolveRouting` 规则如下；已有独立解析/精确居中调用点仍需逐项接入和端到端核对，不能由路由单测推断所有入口都已执行该限制：

| 输入 | 引擎 | 条件 |
|---|---|---|
| 手机内置物理镜头 | Phone WF | 始终使用本地亮星几何解算 |
| 外接相机，系统焦距 >= 200 mm | ASTAP | 使用已安装的 D20/D50 数据库 |
| 外接相机，焦距未知或 < 200 mm | 参数确认 | 要求用户填写焦距和实际视场，暂不自动调用窄场数据库 |

手机链路不得回退到 ASTAP、D20 或 D50。候选不确定时返回可诊断失败，禁止输出坐标。

## 2. 输出契约

`WideFieldSolveRequest` 输入星点、图像尺寸、初始视场、观测时刻、观测地点、亮星目录和可选 IMU 先验。`WideFieldSolveResult` 输出：

- J2000 画面中心：`raDeg`、`decDeg`。
- 画面旋转：`rotationDeg`，范围 `[0, 360)`，以图像 Y 轴相对天球北方向定义。
- 实际宽高视场：`fovWidthDeg`、`fovHeightDeg`。
- 像素尺度：`arcsecPerPixel`。
- 质量：匹配星数、RMS 残差、置信度、是否使用 IMU、是否经过盲解回退、耗时。
- 失败类型：拍摄失败、星点不足、镜头元数据异常、无候选、高残差、候选歧义和设备运动。

`PlateSolveResult` 的公共质量展示应与该结果一致；跨来源的完整契约按 WF-05 接入，不能把手机结果直接包装成已标定镜筒坐标。

**尚待补齐的输出约束（WF-05/06）：**

- 明确图像坐标轴、旋转正方向、像面奇偶性与像素到相机射线映射；提供或可可靠重建完整相机姿态。只有 RA/Dec 中心不足以标定任意偏轴安装。
- 绑定实际物理镜头、光路/参考像素、内参/裁切版本、曝光中点及时间基准；屏幕旋转不得改变物理安装含义。
- 镜面反射显式建模，不能作为普通旋转吸收。输出不完整时可只供画面定位，禁止据此完成需要滚转的安装标定。
- 结果质量、误差和失败/歧义保持原始记录；传播后的指向另存，不能刷新原始绝对解算时刻。

## 3. 动态镜头与视场模型

每帧 `PhoneSkyCaptureResult` 必须保留：

- 逻辑相机 ID、实际物理相机 ID。
- 请求结果中的 `LENS_FOCAL_LENGTH`、`SCALER_CROP_REGION`。
- 传感器物理尺寸、active array、传感器方向、输出尺寸、RAW/YUV 格式。
- 曝光中点时间、实际曝光和 ISO。

有效传感器尺寸按 active array、capture crop 和输出宽高比共同求取。初始视场公式为：

```text
FOV = 2 × atan(effectiveSensorSize / (2 × focalLength))
```

该初值允许求解器在约 ±15% 尺度范围内检索；通过全星点验证后再拟合中心、旋转和尺度。提星后、匹配前优先采用 Camera2 的 `LENS_INTRINSIC_CALIBRATION` 与 `LENS_DISTORTION` 对星点质心做 Brown–Conrady 反畸变；图像与覆盖层保持原始坐标。拍摄请求优先关闭 HAL 畸变校正，无法关闭时依据 capture result 跳过重复校正。缺少设备标定数据时维持原始坐标并在诊断 JSON 中记录。

元数据同步写入拍摄诊断 JSON；FITS 保留焦距、曝光及相机标识。`CameraFovCalculator` 已有针对全幅、数字裁切和 16:9 输出的单测。

## 4. 求解模式

### 4.1 无 IMU 全天盲解

无 IMU 是必需基线。流程如下：

1. 去背景、热像素抑制、星点提取和质心计算。
2. 选择按 SNR 排序且空间分散的 12–24 颗星点。
3. 将星点映射到相机单位球面，构造三角形边长不变量。
4. 查询全天亮星三角形索引，产生姿态候选。
5. 用全部星点做最近邻验证，拟合中心、旋转、尺度并计算残差。
6. 通过匹配数、残差和最佳/次佳候选显著性门限后才返回结果。

当前 `BlindWideFieldMatcher` 已建立 WF-A/B/C 运行时三角形索引和空间验证索引，并以目录对象缓存；并非每帧只有目录遍历。当前首次构建会建立各桶，仍需量化冷启动开销，再做持久化和按需加载。候选聚类/最佳次佳歧义拒绝与对应合成测试已有，尚不代表真实天空误解率已验收。实拍与性能基线现在即可开展，不等待 P2 优化完成。

### 4.2 可选 IMU 先验

IMU 仅用于局部候选限制、加速及旋转提示：

- 先验范围结合视场和中心/旋转不确定度；当前已有逐步放宽旋转约束与全天回退，传感器可信度和范围仍需实拍校准。
- 局部匹配失败必须回退全天盲解。
- 先验偏差 30°、90° 或磁干扰时，以图像验证结果为准。
- `TYPE_ROTATION_VECTOR` 不能作为绝对坐标真值；绝对姿态只能由板解建立。

现有 `ImuAssistedWideFieldSolver` 已接入统一 WF 入口，作为提示模式使用。

## 5. 星表与几何索引

星表采用 APK 内的 HYG v4.1 约 6 等亮星子集：

- 数据：`app/src/main/assets/catalog/phone_hyg_v41_m6.csv`。
- 许可：CC BY-SA 4.0，见 `THIRD_PARTY_HYG.txt`。
- 再生脚本：`tools/generate_phone_bright_catalog.ps1`。

当前运行时已按对角视场 ≥70°、≥45°、其余选择 WF-A/B/C；各桶在首次索引构建时一起生成。以下是 P2 持久化资源与重叠覆盖的目标设计，并非已有二进制资源：

| 桶 | 对角视场 | 覆盖镜头 |
|---|---:|---|
| WF-A | 70°–125° | 超广角、约 14–20 mm 等效 |
| WF-B | 45°–90° | 约 21–35 mm 等效 |
| WF-C | 25°–60° | 约 35–50 mm 等效 |

相邻桶保持重叠。运行时只加载当前桶及必要的相邻桶。生成器须记录 HYG 版本、星等阈值、图案数量、碰撞统计、格式版本及文件大小。

## 6. 图像与短曝光

- 单帧可提取足够亮星时直接解算。
- 单次曝光受限于 0.5 s 的机型，连续采集 8–16 帧并在同一 Camera2 session 内叠加。
- 使用热像素抑制、稳健叠加和帧间位移检测；明显运动帧不进入叠加。
- 保留原帧、堆叠图、星点覆盖层和诊断 JSON，便于区分拍摄、提星和匹配问题。
