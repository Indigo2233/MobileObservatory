## 2026-10-31：导入图像解析时取消导致崩溃

- 用户日志 `app(1) (1).log` 在 17:14:14 记录 `Thread-82` 上未捕获的 `InterruptedIOException: read interrupted by close() on another thread`，栈指向 `AstapRunner.solveAttempt` 的输出读取线程。Android 34 回归使用实际 `Process` 和生产 `AstapRunner`，只将 CLI 命令替换为保持输出管道打开的系统进程；连续两次测试均在首次取消时复现相同异常。无需预览渲染或重复点击即可触发。
- ASTAP 的合并标准输出和错误输出改为写入本次专属目录中的 `process.log`，进程结束后由解析协程读取。取消仍交由 `awaitSolverProcess` 终止进程；删除独立读取线程及共享可变输出缓冲。读取错误由当前解析返回失败，取消异常继续向上传递；正常结束、启动失败和取消均关闭进程流并清理临时日志。
- 极轴解析中的操作改为“放弃解析并重试”。点击后取消本次任务及后续自动步骤，保留当前图像与此前成功采样；清理完成后在主控制区显示“重试解析”“选择图像”，已连接相机且位于可重拍位置时同时提供“重拍”。用户可先修改参数，再启动当前点的新尝试。主图、全屏检查和日志窗口使用相同含义；拍摄、转轴等其他阶段继续提供停止。

## 实施范围

- `PolarSampleSession` 负责每点的采集、实际图像视场检查、解算、失败与取消状态。图像在光学检查和解算前登记；已拍摄但解算失败的图像、原始输出和时间保留在任务状态中。
- `PolarSamplesViewModel` 保留采样记录，查看原图再返回和 Activity 重建后仍可检查。图像位于应用缓存，进程恢复和长期归档尚未作为持久化能力交付；系统可能清理缓存。
- 位置、光学与高级设置折叠，执行时收起；曝光、试拍和流程操作在高级设置之前。横屏并列图像与控制区，竖屏上方常驻图像，控制区独立滚动。
- 采样图在解算开始前交付主预览，失败时保留图像。全屏检查在当前页对话框中复用 `MediaImageInspection`，支持缩放、区域 1:1 与显示直方图；打开、关闭检查窗口保持解算继续运行。图像使用 UInt16 预处理和受限区域读取。试拍图、三个采样点和调整图像按最近事件显示；检查中的图像固定，关闭后返回最新图像。
- 每点提供查看图像、重新解算、选择文件，以及失败后的无架台提示解算；重拍只开放当前采样位置，避免将新轴姿态混入旧点。诊断可展开、选择和复制。无新图像的采集失败明确显示尚未取得图像。
- 每次执行冻结光学参数和搜索策略，视场按实际图像高度、合并倍率、焦距和像元确定。关闭架台提示时使用全天搜索，避免未对准的架台坐标限制搜索区域。
- 失败点重试保留先前成功点；已经完成的转轴不重复执行。转轴被中断、旧点被替换或位置关系不再可靠时，重新开始一组采样。手动挪动架台、改变相机安装或更换设备后应主动重新开始。
- `PolarWorkflowTask` 统一持有采样和解算协程。停止、全局 STOP、返回及离开前台会取消后续拍摄和转轴；ASTAP 沿用可取消的进程等待与退出清理。转轴未启动或超时报告失败，阻止继续采样。
- 拍摄入口使用上述有界单帧采集；曝光等待预算按曝光时长计算，等待期间检查断线和参数变化，并跳过可能在请求前开始的曝光。超时显示等待时长、曝光和最近 SDK 报告。
- 日志增加 `PolarAlign` 与 `PolarCapture` 记录，包含启动参数、每点阶段、图像路径、画幅、曝光、失败及 ASTAP 输出。相机 SDK 和冻结的原生库保持既有版本。
