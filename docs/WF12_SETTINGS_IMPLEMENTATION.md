# WF-12 设置草稿与工作区恢复

日期：2026-10-14。本页是实现清单和验收边界，不把自动化或代码存在等同于真机／新手验收。

## 已落盘的实现

- 全局设置只保留应用、诊断和开发构建的序列设置。设备默认值统一由器材详情进入；拍摄中的滤镜名称／调焦默认值动作转到同一设备编辑器，相机与制冷复用同一相机设置。
- Camera／Focuser／Cover 默认值及滤镜、旋转器、电源名称等复杂编辑采用共享 `SettingsDraftEditor`。保存前文本仅是草稿；有效设备和输入通过检查后才提交。实时曝光、制冷、机械运动等就地控制继续即时执行。
- `SettingsDraftViewModel` 使用 SavedStateHandle 保存原值、编辑值及版本；非法数值和中英文名称不被遥测刷新覆盖。旋转可恢复草稿，进程恢复不会重播未完成的设备写入。
- 保存失败保留草稿和错误；设备改变时保留原设备标题，禁止静默写到新设备。只有明确选择「把此草稿用于当前设备」才重定位。
- 相机／制冷草稿的展示身份与保存复核统一采用驱动限定工厂序列号；匿名相机采用连接实例身份。USB 地址或通用型号相同不能让另一台设备继承旧草稿。
- 工具栏返回、系统 Back、设备 sheet 关闭／下滑、设置页切换和工作区切换复用 Save／Discard／Keep 守卫。异步保存未结束时延后离开；恢复中的退出目标重新绑定实际导航动作。
- 调焦 STOP 始终停止，不因松手前状态改变变成设零。设零需要独立确认；按住运动取消／关闭停止，已计划的绝对 goto 不因普通关闭擅自取消。
- 每个工作区保存自己的子页栈和 SaveableState，已访问页保持 composition 与草稿。切工作区不删除页；实际 Back pop 才清该页状态。隐藏页不接收 Back，设备选择弹窗只在所属前景页显示。
- STACK 同模式、GUIDE、SETTINGS 在所有工作区保持一个全局任务页，重新打开恢复其所属工作区及页；PLAYER 每页保留自己的真实源文件参数。普通子任务可切换工作区，显式预览／播放器沉浸状态暂时隐藏工作区导航。
- 非拍摄工作区根 Back 返回拍摄工作区原任务，不累积切换标签历史；只有起始根适用退出应用规则。丢弃草稿后返回保留的编辑页会重新建立干净草稿，保持可编辑。

既有局部草稿、设备切换、保存失败、调焦 STOP 和相机／制冷真实壳层入口回归已有模拟器通过记录，详见 [实施账本](WF_REMAINING_IMPLEMENTATION.md)。本轮新增导航模型测试、SettingsExitRegistry 测试，以及真实壳层「极轴输入→拍摄→星图→恢复」和「设备草稿→工作区守卫→旋转→丢弃→返回编辑」；最新统一构建／执行结果由该账本记录，文件落盘不代表已通过。

现场仍需验证 S23 Ultra 原闪退入口、真实设备写入失败／拔插／设备更换、键盘与系统边缘手势取消、横竖屏和大字体下的返回与工作区切换，以及两名新手完成全部 UX 流程。传输层没有设备确认的参数，保存成功只表示当前实现已完成写入／持久化流程，不能声称固件已确认。DBE、目标／构图和其他业务编辑器各有自己的任务契约；本页不宣称所有编辑器都已经迁移为设备默认值模型。
