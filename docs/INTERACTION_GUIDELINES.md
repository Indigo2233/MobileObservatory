# Indigo Observatory 交互规范与优先改造计划

> 2026-10-13。交互质量列为下一阶段的 **P0 产品主线**。本文件是新建/修改界面的共同约束；[观测流程设计](OBSERVING_WORKFLOW_DESIGN.md)是首批应用实例，[TODO](../TODO.md)记录实施。2026-10-14 已实施第零批基线和第一批主要路径，实际完成证据与余项见 [WF 批次验收](WF_PHASE_0_1_ACCEPTANCE.md)。

## 1. 优先级和适用范围

下一阶段先让用户找得到、退得回、看得懂状态并能连续完成任务，再扩大功能入口。导航、分类和状态衔接应作为功能完成条件，与算法和设备能力一起设计，不再放到功能完成后的“界面优化”尾项。

本阶段以 WF-00、WF-01–04、WF-12 和 WF-11 的相关交互验收为优先交付范围。设备失控、崩溃、数据丢失和科学结果错误仍可先修；数据采集、独立协议工作和算法验证可继续进行。新的用户入口必须遵循本文，不能在首批改造期间继续增加一套不相容的导航。

规范适用于全应用，包括星图、校准、相机、EAA、后处理、文件、器材和设置。先修用户已经指出的典型问题，再用相同规则巡检其他页面；每次只交付可完整走通的小流程。现有暗色/红光主题、设备独立连接、全局 STOP 和科学处理边界继续保留。

规则中的点击次数和层级是本项目的设计预算，不是平台强制数字。特殊任务确需更深层级时，在设计/PR 中说明原因和返回路径即可，不新增逐项用户审批流程。

## 2. 借鉴什么，如何转化

以下依据来自已查阅的一手说明；本项目的具体分组和操作预算属于设计判断，不是对参考产品界面的复制。

| 参考 | 可借鉴的原则或流程 | 在本项目的落点 |
|---|---|---|
| [Android 导航原则](https://developer.android.com/guide/navigation/principles) | 稳定的起始目的地、可预测的返回栈；应用内 Up/Back 对应，工具栏 Up 不退出应用，外部跳入有平台边界 | 子页回实际来源，应用起始根页不放会退出的工具栏返回箭头；单独测试外部打开文件 |
| [NN/g：渐进呈现](https://www.nngroup.com/articles/progressive-disclosure/) | 先呈现高频选择，低频和复杂选项按需展开 | EAA 首屏给开始、拉伸/亮度、保存；校准帧、手动 DBE 和算法参数各有明确次级入口 |
| [NN/g：识别优于回忆](https://www.nngroup.com/articles/recognition-and-recall/) | 可识别的选项、最近项目和上下文提示减少记忆负担 | 入口带名称；我的拍摄可直接找到；需要时解释下一步，不要求记住目录、缩写或开场教程 |
| [StarSense Explorer 官方流程](https://www.celestron.com/pages/starsense-explorer-technology) | 在星图/今夜推荐选天体后直接获得指向引导 | 目标库、目标卡和推镜属于同一观测上下文，不让用户先找到硬件标签页 |
| [Android / Material 3 底部面板](https://developer.android.com/develop/ui/compose/components/bottom-sheets) | 平台提供可展开与关闭的 sheet 容器 | 短时设备控制就地展开；多步校准采用明确的完整子流程，不连续套多个 sheet |

## 3. 全应用十条交互约定

| 编号 | 约定 | 检查方式 |
|---|---|---|
| IG-01 | 按用户任务分类，每个功能有一个明确归属；就近快捷入口复用该功能 | 新手不需要知道设备协议或源码模块，能判断去哪里找 |
| IG-02 | 先确定当前对象/任务，再给动作；首屏一个突出主操作，必要次操作低强调 | 星图目标卡、EAA 和器材面板都能看出现在在做什么、下一步是什么；STOP 独立可达 |
| IG-03 | 高频操作靠近工作画面；导航、筛选、状态、操作不混成几排类似 Tab | 一级目的地、内容分类和按钮的外观/语义能区分 |
| IG-04 | 返回可预测，一次退出一个可感知层级 | 系统返回、工具栏返回、关闭按钮符合本文行为矩阵，取消手势不提交变化 |
| IG-05 | 手势有明确对象，重要能力同时有可见入口 | 空白关闭、拖动画布、列表滚动和系统边缘返回不互相抢占；不靠隐藏手势找功能 |
| IG-06 | 导航保存上下文，动作具有明确效果 | 调设备回来目标/图像/参数还在；关闭面板不暗中改任务或断线 |
| IG-07 | 状态、等待和失败都有可操作的表达 | 看得到进行到哪、缺什么、下一步怎么恢复；不只有转圈、灰按钮或路径字符串 |
| IG-08 | 按实际能力推荐流程，缺条件就地补齐 | 无架台、目镜、双相机各有可用路径；不会把“已连接”展示成“已校准” |
| IG-09 | 默认简单，进阶可发现；用短句和具体动作命名 | 不强制阅读技术说明，不用含混“确定”替代保存、同步或移动 |
| IG-10 | 夜间、单手、小屏和辅助功能纳入设计 | 红光、大字体、横竖屏、触控范围、文字与图标状态均可用 |

这些规则必须在实际操作路径上成立；页面单独看来整洁，不能作为整条流程好用的证据。

## 4. 建议的信息架构

### 4.1 四个一级工作区

目标结构改为 **星图 / 拍摄 / 影像 / 器材**。这是本轮提出的改造目标，替代上一版暂时保留五标签的安排，已完成路径原型并进入代码迁移；新手首次找入口验证尚待真人参与。沿用当前底部/侧边自适应导航组件及视觉风格；首次实施保留“拍摄”为应用起始页，不把启动页变更和分类改造绑在一起。

| 一级工作区 | 用户任务 | 主要内容 |
|---|---|---|
| 星图 | 找目标并把望远镜指过去 | 搜索、目标库、今夜推荐、视场、推镜/GOTO/居中、观测准备 |
| 拍摄 | 对焦、采集与实时观看 | 预览、拍照、录像、EAA、对焦、导星及准备条件；最近拍摄缩略图 |
| 影像 | 找回、查看和处理已有素材 | 最近、照片、录像、叠加结果；打开后按文件能力提供处理、导出/分享，外部导入为次要入口 |
| 器材 | 管理设备和光路 | 连接清单、单设备完整控制、主镜/辅助光路、设备专属设置和诊断 |

顶部设备状态带保留。设置、夜视继续使用全局入口。赤道仪完整控制归入“器材 → 赤道仪”；方向盘/GOTO/跟踪等常用操作在星图或状态带就近可达。减少一级标签不能让常用机械控制更难打开。

“工具”不再作为长期的一级杂项分类。过渡期间保留旧快捷入口时，必须转到新的唯一目的地并保留来源，不能维持新旧两套独立状态。完成迁移的入口及时移除重复导航；确实独立的少用工具放在相关工作区的“更多”，不再新建万能功能大厅。

### 4.2 现有功能归属表

| 功能 | 唯一归属 | 允许的就近入口 |
|---|---|---|
| 目标库、今夜推荐、搜索 | 星图的目标选择 | 拍摄的目标名称入口打开同一选择流程 |
| 推镜、GOTO、指向并居中 | 星图的目标任务 | 当前目标摘要、恢复任务入口；不要求访问器材页 |
| 手机与镜筒校准 | 星图 → 观测准备 → 指向校准 | 开始推镜发现缺条件时就地进入；器材配置可查看同一标定记录 |
| 极轴校准 | 星图 → 观测准备 → 极轴校准 | 拍摄准备按适用模式提供；经纬仪/手动 Dob 不列为强制前置 |
| 赤道仪、调焦器、滤镜轮完整控制 | 器材 → 对应设备 | 状态带直接打开该设备快捷控制；主任务内复用控制组件 |
| 对焦与导星 | 拍摄的准备/运行控制 | 设备状态带、需要该条件的拍摄任务 |
| EAA | 拍摄 → EAA | 星图指向完成后“开始 EAA”；保留既有工作区 |
| 单张解析 | 已打开图像的动作；实时拍摄结果使用同一解析目的地 | 拍摄“更多”、影像详情；参考来源必须明确 |
| 行星后处理 | 影像 → 录像 → 后处理 | 拍摄完成卡、“我的拍摄录像”打开同一素材选择/处理流程 |
| 保存结果与外部导入 | 影像 | 保存后“查看”、拍摄最近缩略图；使用同一媒体索引 |
| BIAS/DARK/FLAT 校准帧 | 使用它们的叠加任务 → 校准帧 | 影像中从符合条件的素材创建；与手机指向校准明确区分 |
| GC / 手动 DBE / 去马赛克 | 图像或叠加任务的调整/高级设置 | 只在适用素材和阶段显示；保留现有默认值和科学处理规则 |
| 序列 | 开发构建中拍摄的高级任务 | 继续受 `SequenceFeature.ENABLED` 控制，发布包没有入口 |

影像首屏用“照片、录像、叠加结果”等可识别分类，并显示日期、目标/缩略图和最近结果。文件格式、原始目录与诊断信息可展开；“素材”和“结果”无需做成两套文件浏览器。

## 5. 层级与页面容器

常规流程以“工作区 → 当前对象/任务 → 详细设置”三层为设计预算。校准步骤属于一个任务内的进度，不每一步再包一层页面。增加层级前先检查是否能内联展开、按任务分组或省去重复选择。

| 内容 | 优先容器 | 行为边界 |
|---|---|---|
| 持续工作与大图交互 | 工作区或完整任务页 | 保留上下文，长任务可恢复，主操作位置稳定 |
| 目标、滤镜、某个短参数选择 | 明确的选择面板/列表 | 显示当前值；完成后回原处，不去全设备总页 |
| 短时设备控制 | 就地快捷面板，宽屏可侧栏 | 多步设置再进入完整详情；不在 sheet 里继续叠 sheet |
| 常用高级参数组 | 页面内展开组或独立设置页 | 展开前有有效摘要；不能把主要操作埋进多个“更多” |
| 多步校准 | 完整子流程 | 每步一个目的，显示进度、返回上一步，必要时保存草稿 |
| 必须作出选择的确认 | 对话框 | 只用于真实后果或不可撤销操作，不为切页、展开和关闭常规加确认 |
| 成功反馈 | 就地状态/短提示 + 有用后续动作 | 保存后可直接查看，不强制跳走或只给文件路径 |

全局状态、页面标题、任务摘要各自只承担自己的职责。默认不同时铺满设备总览、第二排全设备 Tab、第三排任务 Tab 和工具按钮。状态摘要在不相关页面收起为必要信息；有运行任务时提供明确的恢复入口，不能再变成一个功能导航栏。

## 6. 返回与手势行为矩阵

| 场景 | 系统返回/边缘手势 | 工具栏/关闭与其他手势 |
|---|---|---|
| 输入法显示 | 按系统规则先收起输入法 | 不把收起输入法当作退出任务 |
| 弹窗、菜单、快捷面板 | 关闭最上层 | 关闭按钮产生同一效果；没有未保存编辑时点遮罩可关闭 |
| 星图目标卡/信息层 | 先收起该层 | 空白短按收起、保留所选目标；同一次点按不穿透到画布动作 |
| 全屏观测/图像放大模式 | 先退出全屏/放大模式 | 回所属任务普通视图，保留图像、参数和运行状态 |
| 完整任务/编辑页 | 回上一步或实际来源 | 返回相同来源；确有未保存内容才提供保存/放弃选择 |
| 非起始一级工作区根页 | 回应用起始页“拍摄”，不累积所有标签切换历史 | 根页不放伪装成“上一级”的跨标签返回按钮，使用主导航切换 |
| 应用起始根页 | 由系统离开 Activity | 不显示用于退出的工具栏 Up 按钮 |
| 外部应用打开文件/链接 | 遵循系统任务栈，可能返回外部调用者 | 工具栏 Up 保留在本应用的合理父目的地；作为应用内同源返回规则的明确例外 |
| 画布拖动、双指缩放、列表横滑/纵滚 | 系统边缘区域遵循系统返回 | 内容区域手势不模拟“横划退出”；取消预测性返回不改状态 |

Android 的系统 Back 与工具栏 Up 在外部任务边界并不完全相同；不要为追求“所有地方同一回调”而破坏平台语义。应用内正常进入的子流程仍要求来源一致，详见 [Android 导航原则](https://developer.android.com/guide/navigation/principles)。

点同一面板入口可关闭，打开另一互斥面板则切换。自动隐藏只作用于可恢复的非关键信息；锁定浮层不取消主动关闭能力。停止运动、录制/叠加状态和正在等待的关键确认不能被超时隐藏。按住移动的控件在松手、取消、失去交互时停止；打开任何面板后必要的 STOP 仍可达。

## 7. 状态、文案与渐进呈现

| 状态 | 主区域表达 | 就近动作 |
|---|---|---|
| 缺少条件 | 一句指出当前缺项，例如“还未校准手机与镜筒” | “开始校准”；已有信息自动带入 |
| 可开始 | 当前目标/光路与有效状态 | “开始推镜”“开始叠加”等具体动作 |
| 运行中 | 实际阶段与必要数值，例如“正在拍摄定位图” | 明确暂停/停止/取消；不重复启动 |
| 暂不可精确判断 | “暂用估计方向”等诚实状态 | “重新定位”，而非把图标变绿 |
| 失败 | 简短原因，保留参数/素材 | “重试”“连接设备”等恢复动作；详细日志展开 |
| 完成 | 成功对象与结果 | “查看图片”“继续观测”，不强制丢失工作区 |
| 没有内容 | 解释这里会出现什么 | “前往拍摄”或“导入”，不要求知道存储路径 |

同一上下文中只突出一个推荐主操作，但必要次操作仍可见。例如目视“同步”可以作为低强调次操作与 GOTO 同层；STOP 不受单一主操作原则限制。能力变化不能让一个正在按下的按钮悄悄变成另一项有副作用的动作。

常用参数在主层，高级参数有明确名称和当前摘要，专家直接展开即可，不另造与新手路径分离的整套模式。保留当前自动 GC、可选校准帧和去马赛克默认值；“支持更多算法”本身不构成新增一级入口的理由。

区分三类动作：“校准手机与镜筒”建立安装关系，“同步赤道仪”写入控制器，“移动到目标”驱动架台。字段含单位，未知值显示未知；连接、可用、已校准、已验证分别呈现，不能由一个绿色图标包办。

解释默认一条短句，操作按钮写结果明确的动词；具体错误在发生处帮助恢复。技术背景、源坐标、诊断和路径放在详细层。新手提示按需出现、可关闭；不要用常驻教程墙补救分类错误。

## 8. 用现有问题约束路径长度

以下预算从指定起点计算，仅统计界面导航点按，不包含输入、物理安装、拍摄等待或有必要的确认；不能为了少一次点击跳过校准/质量检查。

| 任务与起点 | 目标操作路径 | 预算/验收 |
|---|---|---|
| 星图已选目标，指向条件就绪 | 目标卡 → 开始推镜或对应指向动作 | ≤2 次点按进入运行；无赤道仪页绕行 |
| 任一工作区调整已连接滤镜轮/调焦器 | 顶部该设备 → 可操作面板 | 1 次打开控制；关闭后原工作区保持 |
| 未连接设备但正在观测 | 状态/准备提示 → 该类设备连接 → 继续原任务 | 不再经过设备总览二次分类；取消返回原任务 |
| 星图找极轴校准 | 观测准备 → 极轴校准 | ≤2 次打开流程；条件不符就地说明 |
| 保存后立刻查看 | 成功反馈 → 查看 | 1 次；返回原叠加/拍摄上下文 |
| 之后找回拍过的图片/录像 | 影像 → 最近项目 | ≤2 次打开最近素材；无私有目录查找 |
| 星图关闭打开的信息层 | 点空白或系统返回 | 1 次关闭一层，目标仍在；不退出应用 |

低保真编排示例：

```text
顶部：已有设备状态带                          夜视 / 设置
星图：搜索/目标库                         观测准备
      画布 + 当前目标/指向状态
      目标卡：目标名称  [开始推镜]  次要动作
底部：星图        拍摄        影像        器材

点“调焦器” → 原星图上展开位置/步长/移动/停止
关闭面板   → 同一目标、同一视场、同一引导任务
```

这份示例表达层级与动作关系，不规定新的配色或美术样式；屏幕空间不足时调整布局，不能用缩小触控区或藏掉返回来强行保持外观。

## 9. 新界面的最小设计记录

新增或修改入口时，在相关设计/PR 中填清下列事项；小改动只更新受影响项，不要求每次重写长文。

| 项目 | 必须说明 |
|---|---|
| 用户任务与归属 | 用户要完成什么，唯一目的地在哪里，快捷入口有哪些 |
| 当前上下文 | 哪个目标、光路、设备/文件，来自哪里，回来恢复什么 |
| 主要操作 | 首屏动作、前置条件、设备副作用与是否已得到任务授权 |
| 层级与返回 | 使用页面/sheet/展开组的理由；返回、点空白、手势取消的结果 |
| 状态 | 空、忙、缺条件、失败、完成如何表达和恢复 |
| 保持与失效 | 切页、旋转、断线、进程重建后哪些可保留，哪些需重新验证 |
| 验收 | 相应 UX 场景、路径点按数、导航/状态验证与真机缺口 |

例：滤镜轮的归属是器材详情，快捷入口是顶部状态；上下文是当前 EAA；首屏显示当前滤镜和切换；关闭返回 EAA；叠加运行中按原有校准/参数规则处理换滤镜，不能因为做成快捷面板就绕过限制。
