Player One Camera Android SDK API

playerone-camera-sdk-release.aar 的应用层集成与公共 Java API 文档。 本文档对应 Android 移植 Phase 3，覆盖 USB 生命周期和现有 37 个 Player One Camera C 接口的类型化 Java 封装。

minSdk 24 compileSdk 34 arm64-v8a armeabi-v7a USB Host Phase 3

概览

真机验证 当前 AAR 已包含现有 37 个 Player One Camera C 接口的 Java/JNI 等价入口、固定宽度 V2 配置接口和 DirectByteBuffer 图像读取。 Samsung Galaxy Tab S7+ / Android 10 和 Xiaomi 15 / Android 16 已使用多个相机通过 Phase 3 流程。Xiaomi 首次测试退出是 USB 供电不足所致，改用独立供电 USB Hub 后通过。

AAR 内已经包含：

  • jni/arm64-v8a/libPlayerOneCamera.so
  • jni/arm64-v8a/libusb-1.0-po.so
  • jni/armeabi-v7a/libPlayerOneCamera.so
  • jni/armeabi-v7a/libusb-1.0-po.so
  • 公共 Java 类和内部 JNI bridge
  • JNI 方法所需的 consumer ProGuard keep 规则
  • android.hardware.usb.host manifest feature 声明

应用不需要单独打包上述 .so，也不需要直接调用 JNI 或管理 USB fd。 libusb-1.0-po.so 使用 Player One 专用 ELF SONAME，可与其他名称的 libusb 共存；不要使用 Gradle pickFirst 覆盖任一厂商的 native library。

集成 AAR

  1. 将 playerone-camera-sdk-release.aar 放入应用模块的 app/libs/。
  2. 在应用模块的 Gradle 配置中添加本地 AAR 依赖。
  3. 宿主工程必须使用 compileSdk 34 或更高版本。
  4. 确保测试设备支持 USB Host，并且应用进程 ABI 为 arm64-v8a 或 armeabi-v7a。

USB 权限 不需要在 manifest 中声明普通运行时 USB 权限。应用通过 UsbManager.requestPermission() 触发系统 USB 授权对话框；该过程由 PlayerOneUsbManager 封装。

生命周期

创建 manager → refreshDevices → requestPermission → authorized → diagnostic → close
  1. 通常在 Activity、Fragment 或业务组件启动时创建一个 PlayerOneUsbManager。
  2. 显式调用 refreshDevices() 建立当前 USB 设备快照。未授权的支持设备也会出现在结果中。
  3. 对目标设备调用 requestPermission()。只有 callback 的 granted == true 才表示系统授权和 native fd bind 都成功。
  4. 授权成功后，可在后台线程调用 runSingleFrameDiagnostic()。
  5. 组件销毁时调用 close()。关闭后不能再调用其他 manager 方法。

拔出设备时，SDK 接收 Android detach 广播，先注销 native registration、停止并关闭 native 相机状态， 然后关闭 Java 持有的 UsbDeviceConnection。重复 detach 和重复 close() 是幂等的。

Kotlin 快速开始

import android.app.Activity
import android.os.Bundle
import com.playeroneastronomy.camera.PlayerOneUsbManager
import com.playeroneastronomy.camera.PoaException
import com.playeroneastronomy.camera.UsbCameraDevice
import java.util.concurrent.Executors

class CameraActivity : Activity() {
    private lateinit var usbManager: PlayerOneUsbManager
    private val cameraExecutor = Executors.newSingleThreadExecutor()
    private var cameras: List<UsbCameraDevice> = emptyList()

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        usbManager = PlayerOneUsbManager(this)
        refreshCameras()
    }

    private fun refreshCameras() {
        try {
            cameras = usbManager.refreshDevices()
            val camera = cameras.firstOrNull() ?: return

            if (camera.isAuthorized) {
                runDiagnostic(camera)
            } else {
                usbManager.requestPermission(camera) { authorizedCamera, granted ->
                    if (granted) {
                        runDiagnostic(authorizedCamera)
                    } else {
                        // 用户拒绝，或 UsbDeviceConnection/native fd bind 失败。
                    }
                }
            }
        } catch (error: PoaException) {
            handleSdkError(error.errorCode, error.message)
        }
    }

    private fun runDiagnostic(camera: UsbCameraDevice) {
        cameraExecutor.execute {
            try {
                usbManager.runSingleFrameDiagnostic(camera)
                runOnUiThread {
                    // open/init/control/bulk/stop/close 全部成功。
                }
            } catch (error: PoaException) {
                runOnUiThread {
                    handleSdkError(error.errorCode, error.message)
                }
            }
        }
    }

    private fun handleSdkError(code: Int, message: String?) {
        // 记录 code 和 message；不要只根据 message 做业务判断。
    }

    override fun onDestroy() {
        usbManager.close()
        cameraExecutor.shutdown()
        super.onDestroy()
    }
}
不要阻塞主线程 runSingleFrameDiagnostic() 是同步阻塞调用，包含曝光等待和 bulk image read，必须放在工作线程执行。 refreshDevices() 和权限请求建议从主线程发起。

完整相机接口

USB 授权成功后，通过 PlayerOneCameraSdk 枚举相机，再用 PlayerOneCamera 完成控制。Java 层不复制 native 状态机；所有返回码统一转换为 PoaException，其 getError() 返回类型化 PoaError。

完整单帧示例

val camera = PlayerOneCameraSdk.getCamera(0)
camera.open()
try {
    camera.initialize()
    camera.imageFormat = PoaImageFormat.RAW8

    val size = camera.imageSize
    val bytes = size.requiredBytes(PoaImageFormat.RAW8)
    require(bytes <= Int.MAX_VALUE)
    val image = ByteBuffer.allocateDirect(bytes.toInt())

    camera.startExposure(true)
    try {
        while (!camera.isImageReady) Thread.sleep(10)
        camera.getImageData(image, 5000)
    } finally {
        camera.stopExposure()
    }
} catch (error: PoaException) {
    Log.e("Camera", "${error.error}: ${error.message}", error)
} finally {
    camera.close()
}
工作线程要求 getImageData() 会阻塞，曝光轮询和取图必须在工作线程执行。不要在主线程执行上述单帧流程。

PoaError 与 PoaException

PoaError 完整覆盖 0 到 17：OK、INVALID_INDEX、INVALID_ID、INVALID_CONFIG、 INVALID_ARGUMENT、NOT_OPENED、DEVICE_NOT_FOUND、OUT_OF_LIMIT、EXPOSURE_FAILED、TIMEOUT、 SIZE_LESS、EXPOSING、POINTER、CONFIG_CANNOT_WRITE、CONFIG_CANNOT_READ、ACCESS_DENIED、 OPERATION_FAILED、MEMORY_FAILED。捕获异常后优先判断 error.getError()，不要解析消息文本。

DirectByteBuffer 约束

  • 必须使用 ByteBuffer.allocateDirect(requiredBytes)；heap buffer 立即抛出 IllegalArgumentException。
  • 所需容量为 width * height * bytesPerPixel；容量不足返回 PoaError.SIZE_LESS。
  • timeoutMs == -1 表示无限等待，其他值必须非负。
  • native 调用期间保留 buffer 强引用，不要在另一线程并发读写或复用同一 buffer。
  • 连续采集建议复用 2 到 3 个 direct buffer，避免每帧分配和 GC 抖动。
  • JNI 写入从 buffer 基地址开始；调用前请按完整容量分配，不依赖 position/limit 作为 native 偏移。

PlayerOneUsbManager

com.playeroneastronomy.camera.PlayerOneUsbManager

Android USB Host 生命周期入口。负责扫描支持的 Player One 设备、申请权限、保持 UsbDeviceConnection 强引用、绑定 fd、响应 detach，并按正确顺序释放 native 与 Java 资源。

构造函数

public PlayerOneUsbManager(Context context)

使用 application context 获取系统 UsbManager，并注册权限结果与 USB detach receiver。

参数说明
context任意有效 Android Context；SDK 内部保存其 application context。

异常：USB Host service 不可用时抛出 IllegalStateException。

refreshDevices

public synchronized List<UsbCameraDevice> refreshDevices()

读取 UsbManager.getDeviceList()，注册所有 VID/PID 受支持的 Player One 相机， 清理已经断开的记录，并刷新 native camera count。

  • 返回不可修改的列表快照。
  • 未授权设备也包含在列表及 native count 中。
  • 同一次连接重复 refresh 保持相同 registration ID。
  • 非 Player One VID 或不支持的 PID 被忽略。
  • 建议在第一次查询 count 或请求权限前调用。

关闭 manager 后调用会抛出 IllegalStateException。

requestPermission

public synchronized void requestPermission(
    UsbCameraDevice device,
    PlayerOneUsbManager.PermissionCallback callback)

请求 Android USB 权限；授权后打开 UsbDeviceConnection 并将 fd 绑定到 native registration。

参数说明
device当前 manager 的最近一次 refreshDevices() 返回的设备。
callback权限与 fd bind 的最终结果。必须传入非 null callback。
Callback 可能同步执行 如果 Android 已经授予该设备权限，callback 会在 requestPermission() 返回前执行；否则在系统权限广播到达后执行。 调用方必须兼容两种情况。

granted == true 表示系统权限、UsbDeviceConnection 打开和 native fd bind 均成功。 false 表示用户拒绝或授权后的打开/bind 失败。

设备已失效时抛出 IllegalArgumentException；manager 已关闭时抛出 IllegalStateException。

PermissionCallback

public interface PermissionCallback {
    void onResult(UsbCameraDevice device, boolean granted);
}

单方法接口，可直接使用 Kotlin lambda 或 Java lambda。

getCameraCount

public synchronized int getCameraCount()

返回 native registry 当前可见的 Player One 相机数量。计数包含尚未授权的相机。

建议先调用 refreshDevices()；manager 已关闭时抛出 IllegalStateException。

runSingleFrameDiagnostic

public void runSingleFrameDiagnostic(UsbCameraDevice device)

执行同步单帧诊断：

  1. 刷新并解析 camera ID；
  2. open 和 init；
  3. 设置 RAW8；
  4. 启动单次曝光并等待图像就绪；
  5. 读取完整单帧 bulk 数据；
  6. stop 和 close。

成功时无返回值；任一步失败时抛出 PoaException。

阻塞调用，必须在工作线程执行。未授权时抛出错误码 15。

close

@Override
public synchronized void close()

注销 receiver 和所有 native registration，并在 native 清理完成后关闭 Java UsbDeviceConnection。重复调用安全且无效果。

关闭后，除重复 close() 外，其他 manager 方法不可再调用。

UsbCameraDevice

com.playeroneastronomy.camera.UsbCameraDevice

一个已连接且受支持的 Player One USB 设备。对象由 PlayerOneUsbManager 创建，应用不能直接构造。

方法返回值与语义
String getDeviceName() Android USB device path，例如 /dev/bus/usb/001/002。只用于本次连接。
int getVendorId() USB Vendor ID；Player One 设备通常为 0xA0A0。
int getProductId() USB Product ID；例如 Uranus-C 为 0x5850。
int getRegistrationId() native registry 为本次连接分配的正整数身份。授权前后保持不变；detach/reconnect 后会变化。
boolean isAuthorized() 只有 Android 权限和 native fd bind 都成功时才为 true。
不要持久化设备身份 deviceName、Android device ID 和 registrationId 都不是相机序列号。 它们只能标识当前 USB attach 会话，不能写入数据库作为永久相机身份。

线程与断开处理

  • 在主线程创建和关闭 PlayerOneUsbManager，并从主线程发起 refresh 与权限申请。
  • 权限 callback 通常由 Android 广播线程（主线程）调用；已有权限时可能在调用线程同步执行。
  • runSingleFrameDiagnostic() 必须在专用工作线程执行。
  • 不要在 diagnostic 进行中主动调用 close()；真机 detach 会由 SDK 协调清理。
  • detach 后旧 UsbCameraDevice 立即失效。重新连接后必须再次 refresh，并使用返回的新对象。
  • 不要自行关闭或复制 SDK 内部持有的 USB fd。

常见问题

现象检查项
PlayerOneUsbManager 是否必须全进程单例？主相机和导星相机是否需要各自的 manager？ API 不强制使用静态单例，但当前 native registry 是进程级全局状态，而每个 manager 分别持有自己的 USB connection、权限 callback 和广播接收器。因此同一进程应共享一个长期存在的 PlayerOneUsbManager，不要为每台相机、Activity 或 Fragment 分别创建实例。一个 manager 可以同时枚举、授权并维护主相机和导星相机；不同 USB 设备会使用不同 registration ID 和 fd。多个 manager 操作同一设备时会获得相同 registration ID，但可能尝试绑定不同 fd，或者在其中一个 manager 关闭时注销另一个仍在使用的全局 registration。
refreshDevices() 返回空列表 确认手机支持 USB Host、Hub 已独立供电、VID 为 0xA0A0、PID 受支持，并重新插拔后 refresh。
权限 callback 返回 false 用户可能拒绝授权；也可能是 UsbManager.openDevice() 或 native fd bind 失败。
错误码 15 错误码 15 是 ACCESS_DENIED。未授权设备执行 diagnostic 会返回该错误；同一 registration ID 已绑定一个 fd 后，再绑定另一个 fd 也会返回该错误。重复注册同一设备会返回原 registration ID，重复绑定 同一个 fd 则是幂等成功。请确认只在权限 callback 返回 true 后操作设备，并确保进程内共享同一个 PlayerOneUsbManager。
运行 diagnostic 时 APP 退出或 USB 连接中断 优先检查 USB 供电和线材；使用独立供电 USB 3 Hub 后复测。Xiaomi 15 / Android 16 的首次退出由供电环境导致。
UnsatisfiedLinkError 确认 APP 进程 ABI 为 arm64-v8a 或 armeabi-v7a，AAR 未被错误解包，并且对应 ABI 目录内同时包含两个 native library。
PlayerOneUsbManager is closed 不要复用已经 close 的 manager。由应用级 USB owner 创建并共享新的 manager，不要由每个 UI 组件分别持有实例。
